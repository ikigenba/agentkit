# Phase 75 — `ocr`: the `OCR` tool, its cache, and its preview

*Realizes design Decision 31 (the `ocr` package surface). Depends on Phase 73 and Phase 74.*

Completes `ocr` with the consumer-facing surface: `Tool(root, cacheDir string, backend *OpenRouter) agentkit.Tool`, built on the existing `agentkit.NewTool` constructor (D4), declared to the model as `OCR` with a single `file_path` input.

Observable end state: calling the tool confines the source path to `root` (symlink-resolved, per D27's rule) **before** any network call, extracts via Phase 74, and writes a cache entry directory `<cacheDir>/<source-stem>-<hash8>/` containing `response.json` (the provider body verbatim) and `transcript.md` (derived by `Transcript`). A repeat call on unchanged bytes serves from cache with no request; a missing `transcript.md` is regenerated from `response.json` with no request; changed source bytes miss and re-extract. The result is always one shape — a preview plus the `transcript.md` path — where the preview is a verbatim prefix of the transcript, capped at 30,000 characters, cut at the last page boundary that fits, falling back to a line boundary when a single page exceeds the cap, and marked explicitly as either complete or truncated with shown-versus-total figures. A failed extraction writes nothing. `response.json` is never named in the result.

Tests point `OpenRouter.BaseURL` at an `httptest` server so request counts are directly observable, which is what makes the cache-hit and no-call-on-rejection ids falsifiable rather than assumed.

**Done when** the suite is green (`go build ./...` and `go test ./...` both exit 0, per design Conventions) and each id below is covered by a clearly-named test in `ocr/*_test.go` tagged with the bare id:

- R-V1UC-V54E — declared name is `OCR`; input schema has exactly one property, `file_path`, and no output-path field.
- R-V329-8WV3 — a path escaping `root` (via `../` or a symlink) is rejected and the recorded request count stays 0.
- R-V4A5-MOLS — success writes exactly `<cacheDir>/<stem>-<hash8>/response.json` and `transcript.md`, with `hash8` the first 8 hex chars of the source bytes' SHA-256.
- R-V6PY-E836 — editing the source bytes yields a different cache directory and a new request; the prior directory remains intact.
- R-V7XU-RZTV — a second call on unchanged source issues no request and returns the same transcript path.
- R-V95R-5RKK — with `transcript.md` deleted and `response.json` present, it is regenerated byte-identically with no request.
- R-VADN-JJB9 — a transcript at or under 30,000 characters is returned in full, marked complete.
- R-VBLJ-XB1Y — a transcript over 30,000 characters is returned as a verbatim prefix, ≤ 30,000 chars, ending at a page boundary, marked with shown pages, shown characters, and total characters.
- R-VCTG-B2SN — when page 1 alone exceeds the cap, the preview falls back to a line boundary and stays ≤ 30,000 characters.
- R-VE1C-OUJC — a failed extraction leaves no cache directory, and the next successful call performs a fresh request.
- R-VF99-2MA1 — the result names the `transcript.md` path and never mentions `response.json`.
