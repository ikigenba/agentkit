# Decision 32 — OpenRouter document parsing: the request, the response contract, and `Transcript`

**Decision.** `ocr` extracts text by calling OpenRouter's Chat Completions endpoint with the `file-parser` plugin pinned to the `mistral-ocr` engine, and reads the parsed text from the response's `annotations`, never from the model's generated reply. The fragile part — the wire format — is isolated in one **pure exported function** with no HTTP, no filesystem, and no clock, so it can be tested against recorded real responses.

```go
// package ocr

// Transcript derives the readable Markdown transcript from a raw OpenRouter
// response body. Pure: bytes in, string out. It is exported so a cache can be
// regenerated without an API call, a credential, or the tool.
func Transcript(response []byte) (string, error)

const defaultModel = "google/gemini-2.5-flash-lite"
```

Request shape (research §17.1):

```json
{ "model": "<Model or defaultModel>",
  "messages": [{"role":"user","content":[
      {"type":"file","file":{"filename":"…","file_data":"data:application/pdf;base64,…"}}]}],
  "max_tokens": 1,
  "plugins": [{"id":"file-parser","pdf":{"engine":"mistral-ocr"}}] }
```

Settled choices:

- **Read `annotations`, discard `choices[0].message.content`.** `mistral-ocr` produces the Markdown; OpenRouter injects it into the named chat model's context *and* returns the pre-model text separately under `choices[0].message.annotations[0].file.content`. The chat model contributes nothing: two different model families returned byte-identical transcripts, and a request budgeted `max_tokens: 1` still returned the full 2,403-byte extraction (research §17.2). Reading the reply instead would pay for the model to re-emit text it was handed, and risk it paraphrasing the transcription.
- **The named chat model is a billing knob with no effect on output.** It exists only because `file-parser` is a plugin on `/chat/completions`, which requires a `model`. Design states this explicitly so nobody later "upgrades" it expecting better OCR and silently multiplies the per-page cost. The floor is: **no text content part at all** (verified unnecessary — a file-only request returned the complete transcript), `max_tokens: 1`, and the cheapest model that still reports `usage`. `defaultModel` is `google/gemini-2.5-flash-lite`, chosen because `openai/gpt-5-nano` returned no `usage` block at all, which would silently degrade D16's cost accounting.
- **The model tax is unavoidable and scales with the document.** OpenRouter injects the full extraction into the chat model's prompt, so input tokens are billed over the entire document on every call (1,142 prompt tokens for 2 pages with an empty prompt, 158,051 for 114 pages). This cannot be routed to a cheaper auth path because the plugin exists only on the API-key path. It is the price of keeping documents out of the *agent's* context, and it is why D31's cache is load-bearing rather than a nicety.
- **`annotations` is always exactly one entry.** Verified from 1 to 114 pages: always length 1, always `type: "file"`, named after the uploaded file; everything scales inside `file.content`. `Transcript` asserts the length rather than indexing blindly.
- **`file.content` is a mixed list; keep only `type == "text"`.** Verified structure: a `<file name="…">` sentinel, then one text item per **physical page in order**, with `image_url` items interleaved after the page they came from, then a `</file>` sentinel. The text-item count is exactly *pages + 2* at every size tested. Reading `content` naively is a context bomb — a single page's `image_url` item held 25,409 characters of base64, 94% of that response.
- **Sentinels are matched by pattern, never by index.** Stripping items 0 and *n*-1 positionally would silently treat a real page as a sentinel if the framing ever changes. Matching `<file name="…">` and `</file>` exactly means a format change fails loudly instead.
- **Blank pages hold their slot.** A near-empty page returned its own 1-character item rather than being omitted, so page numbering stays aligned with item ordinal. `Transcript` preserves the slot; dropping empties would shift every later page number.
- **Pages are separated by `<!-- page N -->`.** Markdown passes an HTML comment through, it renders as nothing, it cannot collide with document content, and it is greppable — which matters because a model searching a 114-page transcript needs to report *where* it found something. `--- page N ---` was rejected as not a valid horizontal rule and visually ambiguous next to a table; `## page N` was rejected because it collides with the document's own real `##` headings.
- **Page numbers are physical, not printed.** A statement's physical page 4 printed "Page 3 of 6"; the marker follows the physical page so it matches what a human sees in a viewer and what the item ordinal means.
- **Never trust the HTTP status.** A 413 arrived as **HTTP 200** with `{"error":{"message":"…","code":413}}` as the whole body. Code that branches on status and reaches for `choices[0]` nil-derefs on a failure that looks like success. `Transcript` therefore inspects the body first and surfaces the provider's `code` and `message` verbatim.
- **Empty is an error, never an empty success.** Absent or empty `annotations`, or a zero-length text total after filtering, is a failure. The failure mode this guards is quiet: HTTP 200, a normal-looking response, no annotations — and naive code writes and caches an empty transcript, after which a scanned statement is permanently "blank". A blank *page* inside a good document is data, not an error; only a whole-document empty result fails.
- **Retry uses the shared executor** (`internal/retry`, D21) with the existing transient/rate-limit classification (D7). A body-carried `error` is classified from its `code` field, since the status line cannot be trusted.
- **OCR output is not byte-reproducible.** The same document parsed twice differed at a line break (`Continued\n8/2498/1` vs `Continued 8/2498/1`), independent of model. Live tests therefore assert a **known substring**, never a hash or exact equality, or they flake. Unit tests are unaffected because they run against recorded bytes.
- **Known fidelity limits, recorded so they are not later mistaken for bugs.** The engine is faithful to ink position, not column meaning: a summary-table value landed under *Number* instead of *Amount* in three separate runs. Whitespace inside a cell is unreliable (`EXAMPLE STOREANYTOWNXX` runs merchant, city, and state together). Consumers validate figures against a document's own totals and never split cells on spaces. Bounding boxes and confidence scores, which would let a consumer detect column flattening mechanically, are **not available** through `file-parser`, which returns Markdown only (research §17.6).

**Rejected.**
- *Read `choices[0].message.content`* — pays reasoning/output tokens for the model to re-emit text already handed to us, and lets it paraphrase a financial transcription.
- *Prompt the model to transcribe (native vision)* — the paraphrase path, materially worse for tables, and for images it is what OpenRouter falls back to anyway (D33).
- *An `Extractor` interface as the test seam* — a fake verifies only what its author imagined, while the failure modes here are all wire-shaped (sentinels, per-page ordering, interleaved image items, error-in-a-200). Recorded real responses through a pure function test the thing that actually breaks. See D31 for the deferred-interface stance.
- *Trusting `annotations[0]` without a length check* — one entry is verified across every size tested, but indexing blindly turns a format change into a panic.
- *Mistral OCR direct* — one endpoint for both PDFs and images, roughly half the price, plus bounding boxes and confidence scores; rejected because it needs a second vendor account, and API-key access is routed through OpenRouter (product Scope). The lost geometry is recorded above as a known limitation.
