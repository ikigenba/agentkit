# Decision 6 — Generation settings and the native reasoning value

**Decision.** `Conversation.Gen` holds uniform sampling controls plus a **native-per-model** reasoning value. Reasoning is expressed in the *selected model's own* native term and values — there is **no** cross-model vocabulary and **no** translation. The provider layer is a dumb encoder (D5): the adapter lowers the consumer's `ReasoningValue` to its wire fields **by the value's shape alone** (level / budget / enabled / disabled / unset, D9) and sends it, consulting **no model knowledge**. A wire whose reasoning control has no bare on-form rejects an explicit-enabled value with `ErrInvalidConfig` before sending — a judgment about the *API's shape*, never about the model. A value the model accepts is honored exactly; one it does not accept is rejected by the **vendor**, surfacing as that provider's typed error (D7) — never a silent substitution, never an AgentKit-side fallback. Pre-send validation against a known model's vocabulary is available to consumers as an *advisory* catalog lookup (D26); nothing in the request path performs it.

The consumer sets reasoning with a tagged `ReasoningValue` carrying exactly one native form, so the value flows to the adapter untranslated:

```go
// GenSettings holds uniform generation controls. The zero value is "use each
// provider's defaults": nil/0/unset fields are omitted from the request.
type GenSettings struct {
    Temperature *float64       // nil → provider default (pointer so 0.0 is distinguishable)
    TopP        *float64       // nil → provider default
    MaxTokens   int            // 0 → adapter-supplied default (Anthropic requires a value)
    Reasoning   ReasoningValue // zero value = unset → model default, no reasoning fields sent
}

// ReasoningValue carries exactly one native reasoning form for the selected
// model, flowing to the adapter untranslated. The five states — unset, a native
// level string, a native token budget, explicit-enabled, explicit-disabled —
// are mutually exclusive by construction (unexported fields; built only via the
// constructors below). The zero value is "unset": send no reasoning fields at all.
type ReasoningValue struct { /* unexported: tag + level string + budget int */ }

func Level(s string) ReasoningValue    // a native level string: Level("high"), Level("xhigh"), Level("minimal")
func Budget(n int) ReasoningValue      // a native token budget: Budget(8000)
func EnableReasoning() ReasoningValue  // explicit on; the adapter lowers it to its wire's native on-form
func DisableReasoning() ReasoningValue // explicit off; the adapter lowers it to its wire's native off-form
```

**On and off are independent permissions.** A wire may accept one and reject the other, so `EnableReasoning()` is not a redundant twin of `DisableReasoning()`. It is the only way to reach the reasoning of a model whose provider default is *off* but which has no level vocabulary to name instead — `grok-4.20` emits zero reasoning tokens when nothing is sent and reasons only on an explicit on-value (research §7.1). Without this constructor that model's reasoning is unreachable through AgentKit.

**Not every wire has a bare on-form**, and the adapter says so loudly rather than inventing one. OpenRouter (`{"reasoning":{"enabled":true}}`), Z.ai (`thinking:{"type":"enabled"}`) and Anthropic (`thinking:{"type":"adaptive"}`) each have one. Google and OpenAI express on-ness only as a budget or a level, so their adapters reject `EnableReasoning()` with `ErrInvalidConfig` **before sending**, rather than substituting a budget or a level the consumer did not choose. That rejection is *wire-level* knowledge — the shape of the API, which the dumb layer legitimately owns (D5) — not model knowledge: it depends only on which provider is being addressed, never on which model.

```go
conv.Gen.Reasoning = agentkit.Level("xhigh")     // sent natively; the vendor judges it for the selected model
conv.Gen.Reasoning = agentkit.Budget(8000)       // likewise
conv.Gen.Reasoning = agentkit.EnableReasoning()  // the wire's on-form; a wire without one fails ErrInvalidConfig
conv.Gen.Reasoning = agentkit.DisableReasoning() // the wire's off-form; a model that can't disable rejects it
```

The `Warning` struct remains the shared degrade-and-warn surface for the cases the dumb layer legitimately owns — **wire-level** knowledge (a wire that only supports `tool_choice=auto`; schema constructs a dialect cannot carry) and the **cost-unknown** case (D16). Model-knowledge warnings are gone with the model knowledge:

```go
// Warning records something the library could not do as asked and degraded
// visibly. Every field is meaningful for every warning kind.
type Warning struct {
    Setting string      // "tool_choice" | "cost"
    Code    WarningCode // classifiable reason
    Detail  string      // human-readable: what was asked / what is unknown, what was applied
}

type WarningCode int
const (
    WarnToolChoiceForced WarningCode = iota // forced tool_choice degraded to auto (wire supports only auto)
    WarnCostUnknown                         // no cost source for this call; cost reported as 0 (D16)
)
```

Settled choices:
- **`ReasoningValue` is a tagged carrier with four constructors** (`Level`/`Budget`/`EnableReasoning`/`DisableReasoning`) and an unset zero value — no exported fields, so the five states cannot be combined or half-set. Mirrors the sealed-union idiom of `Block` (D3) and `Event` (D2).
- **`EnableReasoning()` is first-class and independent of `DisableReasoning()`.** Enable-ability and disable-ability are two permissions, not one: `grok-4.5`, `grok-4.20-multi-agent` and `kimi-k2.7-code` accept an explicit on and reject off, while `grok-4.20` defaults to off and needs the explicit on to reason at all. A toggle-shaped model has no level or budget to express "on" with, so without this constructor the on-half of the toggle is unreachable.
- **A wire with no on-form fails loudly rather than guessing.** Google and OpenAI have no bare on-form; their adapters return `ErrInvalidConfig` without sending. Choosing a budget or level on the consumer's behalf would be the silent substitution this whole decision exists to forbid, and it would be a worse failure than an error because the consumer would be billed for a depth they never chose.
- **`Level` takes a raw native string, not a typed enum.** The accepted set differs per model and there is no honest cross-model enum; under free-flow models (D5) the accepted set is not even knowable for uncataloged ids — the vendor is the judge.
- **`DisableReasoning()` is first-class**, not `Level("none")`/`Budget(0)` — *which* value means "off" is wire-specific (`thinking:{type:"disabled"}` vs `reasoning.effort:"none"` vs `thinkingBudget:0`); the consumer expresses intent and the adapter lowers it to its wire's off-form. A model that cannot disable rejects it with the vendor's error.
- **Unset (zero value) sends nothing.** An untouched `GenSettings` sends no reasoning fields, so a consumer who ignores reasoning is unaffected — and a non-reasoning model is safe by default even when uncataloged.
- **No AgentKit-side reasoning validation, fallback, or warning.** The former warn-and-default choke point required per-model specs the provider layer no longer holds (D5). Its replacement is honest fail-loud: the value is sent as given and the vendor's rejection is surfaced typed and attributable. The old promise's *spirit* — never silently misapplied — survives strengthened: nothing is ever substituted at all. Consumers wanting pre-send politeness (validate a `/set` before spending a round trip, render a model's vocabulary in `--help`) call the advisory catalog (D26), outside the request path.
- **Wire-level warnings survive; the enum shrinks and gains `WarnCostUnknown`.** `WarnToolChoiceForced` encodes knowledge about the *API shape*, which the dumb layer owns. `WarnReasoningUnsupported`/`WarnReasoningCannotDisable` are deleted with the model knowledge that powered them. `WarnCostUnknown` is minted for the D16 zero-cost path. `WarnToolSchemaLossy` is deleted with D22's rewrite: a tool schema is now either inside the canonical subset and rendered faithfully, or rejected at the `Send` gate (D34) — there is no degraded-but-sent state left for it to describe.
- **Pointers for `Temperature`/`TopP`** distinguish "unset" (omit) from a deliberate `0.0`. `MaxTokens int` with `0` → adapter-default (supplies Anthropic's required value).

**Rejected.**
- *Warn-and-fall-back-to-the-model's-default on an unsupported value* — the previous design. Requires a per-model spec registry in the provider layer, which is model knowledge (D5 evicts it), gates day-one models, and quietly substitutes a value the consumer did not choose. Vendor rejection is louder and truer.
- *A single neutral `ReasoningEffort` ordinal mapped per provider* — "nearest" is undefinable across a discrete enum and an integer budget; native-first is strictly more truthful.
- *`Level`/`Budget`/disabled as separate exported fields on `GenSettings`* — lets a consumer set more than one (ambiguous); the opaque carrier forbids it.
- *Overloading `Level("none")`/`Budget(0)` for disable* — forces the consumer to know each wire's off-token; `DisableReasoning()` carries the intent.
- *Omitting an on-form, on the theory that "unset already means on"* — false for any model whose provider default is off. It made `grok-4.20`'s reasoning unreachable through AgentKit while the raw OpenRouter API reached it with one field.
- *Lowering `EnableReasoning()` to a chosen budget/level on wires that lack an on-form* (e.g. Google's `thinkingBudget:-1`, OpenAI's `effort:"medium"`) — picks a depth the consumer did not choose and bills them for it; `-1` is also unverified on the Gemini 3.x `thinkingLevel` models. `ErrInvalidConfig` is the honest answer, and the catalog's `CanEnable` tells consumers up front which models take the value.
- *A single `Toggle(bool)` constructor* — collapses two independent permissions into one parameter and reintroduces the half-set ambiguity the tagged carrier exists to prevent.
- *Plain `float64` temperature with a sentinel* — `0.0` is legal; pointer is unambiguous.
- *A sealed `Warning` interface with per-kind variants* — consumers only display warnings; one honest flat struct (D7 precedent) suffices.

**Verification.**
- R-P5U3-5CFZ — a `GenSettings` with `Temperature`/`TopP`/`MaxTokens` set reaches each provider's request with those values; leaving them nil/0 omits the parameter so the provider default applies.
- R-CUBS-CPMC — an adapter lowers any `ReasoningValue` by its shape alone and sends it without consulting model knowledge: no reasoning `Warning` is ever emitted, no fallback value is ever substituted, and a vendor rejection of an unaccepted value surfaces as that provider's typed error while the value that was sent remains exactly the one the consumer constructed (per-provider slices).
- R-T40A-VZQ7 — a `Level`/`Budget`/`DisableReasoning` value reaches the provider adapter as the exact native form it was constructed with, with no cross-model mapping applied between the consumer call and the adapter seam.
- R-T587-9RGW — an unset (zero-value) `Reasoning` omits all reasoning parameters from the built request and produces no `Warning`.
- R-T6G3-NJ7L — the five `ReasoningValue` states (unset, level, budget, enabled, disabled) are mutually exclusive: a value built by one constructor never presents as another at the adapter seam (e.g. a `Budget` value is not readable as a level, and an `EnableReasoning` value reports neither `Disabled()` nor a level nor a budget).
- R-DCOZ-8W8U — `EnableReasoning()` reaches each adapter as its own distinct state and is lowered to that wire's native on-form: OpenRouter emits exactly `{"reasoning":{"enabled":true}}`, Z.ai emits `thinking:{"type":"enabled"}`, and Anthropic emits `thinking:{"type":"adaptive"}` — byte-comparable against the hand-written fragment, with no level or budget field added alongside.
- R-DDWV-MNZJ — the Google and OpenAI adapters reject `EnableReasoning()` with `ErrInvalidConfig` and issue **no HTTP request at all**, rather than substituting `thinkingBudget:-1`, `reasoning.effort:"medium"`, or any other value; the failure is returned before transport (asserted with a transport that fails the test if invoked).
- R-DF4S-0FQ8 — `EnableReasoning()` and `DisableReasoning()` are independent at the adapter seam: on a wire with both forms, each lowers to its own fragment, and neither is derivable from the other (`enabled:true` is never emitted for a disabled value, nor `enabled:false` for an enabled one).
- R-DGCO-E7GX — live (integration-gated, real OpenRouter credentials): against `x-ai/grok-4.20`, whose provider default is off, an unset `Reasoning` returns a completed response reporting **zero** `reasoning_tokens`, while `EnableReasoning()` on the same prompt returns a completed response reporting **more than 100** `reasoning_tokens`. This is the only test that can falsify the claim that the on-form actually turns reasoning on — a mocked transport accepts the fragment either way and proves only that a field was set.
- R-P9HS-ANO2 — a forced `tool_choice` against a Chat-Completions-wire provider that supports only `auto` degrades to `auto` and records a `Warning{Code:WarnToolChoiceForced}` rather than failing.
- R-PBXL-275G — when every requested setting is honored and a cost source exists, `Stream.Warnings()` is empty.
