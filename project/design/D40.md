# Decision 40 — The `xai` provider: Responses on `api.x.ai`, API key and SuperGrok subscription

**Decision.** xAI is a first-class chat provider package `xai` (D5). It speaks the Responses API through the shared internal core that also backs `openai` — never Chat Completions, never the grok CLI proxy (research §20.3). The closed credential set has two members. Both credentials use the **same host, path, and headers**; only the bearer source changes. There is no `NewEmbedder`.

```go
// package agentkit
const ProviderXAI ProviderID = "x-ai" // matches catalog.VendorXAI (D26)

// package xai

type Credential interface{ isCredential() } // closed: exactly two members
type APIKey string                          // platform API, metered
func Subscription(ts TokenSource) Credential // SuperGrok / X Premium, subscription

// TokenSource supplies the living bearer. Implemented by subscription.Store;
// any implementation works. No account id — the public API needs none (research §20.1).
type TokenSource interface {
    Token(ctx context.Context) (bearer string, err error)
}

func New(cred Credential, opts ...Option) *Provider // one wire: Responses (D5)
func WithBaseURL(string) Option
func WithHTTPClient(*http.Client) Option
```

| baked into the handle | `APIKey` | `Subscription` |
|---|---|---|
| endpoint | `https://api.x.ai/v1/responses` | identical |
| auth | static `Authorization: Bearer` | per-request bearer from `TokenSource` — no extra headers |
| body | `store:false`, System→`instructions`, `include:["reasoning.encrypted_content"]` (D9 Responses behaviors) | identical |
| model set | vendor judges (free-flow, D5) | vendor judges; entitlement is the vendor's loud error |
| cost | `usage.cost_in_usd_ticks / 10` → `ReportedCost` nano-USD (research §20.4) | same reported figure |
| `Identity()` (D9) | `{ProviderXAI, AuthAPIKey}` | `{ProviderXAI, AuthSubscription}` |

```go
// package internal/responses — never public. Shared Responses wire used by
// openai and xai. Parameterized by host/path, extra headers, bearer func,
// Identity, Classify, and CostExtractor. openai's subscription transport
// (chatgpt.com + extra headers, D25) is a Config of this core, not a fork.

type Config struct {
    Identity      agentkit.Identity
    BaseURL       string
    Path          string // "/v1/responses" or "/backend-api/codex/responses"
    ExtraHeaders  http.Header
    Bearer        func(ctx context.Context) (string, error)
    HTTPClient    *http.Client
    Classify      func(status int, code, message string) error
    CostExtractor func(usage json.RawMessage) (agentkit.Cost, bool)
}
```

xAI `Classify` maps research §20.6: HTTP 401 `unauthenticated:no-credentials` and HTTP 400 `invalid-argument` whose message is the incorrect-API-key sentence → `ErrAuthentication`; HTTP 400 `Model not found` → `ErrInvalidRequest`; other 4xx/5xx follow the D7 table (429 → rate-limit, ≥500 → unavailable). xAI `CostExtractor` reads `cost_in_usd_ticks` as int64 and returns `Cost(ticks/10)` when the field is present.

`Gen.Reasoning` lowers as OpenAI Responses already does: a `Level` becomes `reasoning.effort`; `EnableReasoning()` is encoded as omission on a model that has no effort field (the grok-4.20 native offering, D26). The vendor judges an unsupported effort.

Settled choices:
- **One provider, one wire, two credentials, one transport.** OpenAI subscription is a different host; xAI subscription is not. Copying D25's dual-transport table onto xAI would invent headers the public API does not require (research §20.3).
- **Shared Responses core, not a copy of `openai/`.** The house pattern when two first-class packages share a wire is `internal/openaicompat` (D5/D24). `internal/responses` is that pattern for Responses. `openai` keeps its public surface and D25 subscription headers as Config; existing openai tests stay the proof that extraction did not change the wire (R-DE1J-AWJ6, R-DF9F-OO9V).
- **TokenSource returns only the bearer.** An unused account-id result would be a lie. The openai `TokenSource` keeps its two-result signature because that backend needs the account header (D25).
- **No embeddings constructor.** Research §20.6: no entitled embedding model. A future embedder is a new Decision.
- **No CLI-proxy path and no official-client impersonation.** Measured 426 without grok-CLI version headers; public `api.x.ai` already accepts the OAuth bearer.
- **Reported cost on both modes.** Ticks match published API rates (research §20.4). D16's reported-beats-supplied rule applies; there is no notional-cost footnote on this package.
- **The Go package is `xai`; the id is `x-ai`.** Same hyphen split as `zai` / `z-ai` (D26).

**Rejected.**
- *A Chat-Completions `xai` adapter via `internal/openaicompat`* — works on the wire (research §20.3) but is the legacy surface and would ignore the Responses core and encrypted-reasoning/tool-item contract already proven for OpenAI.
- *Routing subscription traffic through `cli-chat-proxy.grok.com`* — requires impersonating the official client; lists a subset of models; public API already accepts the token.
- *A second constructor (`NewSubscription`)* — rejected in D5: the credential is the typed parameter.
- *Reusing `openai.TokenSource` (bearer, accountID)* — the second result has nothing to send.
- *`xai.NewEmbedder`* — no entitled embedding model (research §20.6).
- *Baking `~/.agentrepl/xai-auth.json` or `~/.grok/auth.json`* — path discovery is consumer policy; the grok CLI wrapper is a different file shape (research §20.1).
