# Decision 19 — The `EmbeddingProvider` SPI, package architecture & adapter-owned guarantees

**Decision.** A **separate** SPI — `EmbeddingProvider` — is the embeddings seam, parallel to the chat `Provider` SPI (D9) and exported for the same reason (sub-package adapters implement it across a package boundary). It is kept distinct from `Provider` because an embed call has no `System`/`Tools`/`History`/`Gen` and returns no streamed assistant message. Like the chat SPI, it is a **dumb encoder seam** (D5): no pricing method, no model registry, no per-model spec gate — the adapter encodes, authenticates, chunks, normalizes, and maps errors; the vendor judges models, dimensions, and input lengths. Only the two embedding providers expose an embeddings constructor; the package graph and isolation rules of D9 are otherwise unchanged (root never imports a sub-package).

```go
package agentkit

// EmbeddingProvider is implemented by the embeddings-capable provider
// sub-packages (openai, google). Consumers obtain one from a sub-package's
// NewEmbedder and assign it to Embedder.Provider; they do not call Embed
// directly. This is the SPI for adding an embedding provider — distinct from
// the chat Provider SPI (D9), and like it free of model knowledge (D5).
type EmbeddingProvider interface {
    // Embed performs the whole embeddings request for one Embed call: it chunks
    // the batch across the provider's per-call limit, issues the round-trips,
    // L2-normalizes, and reassembles in input order. The D11 retry policy,
    // executed by the shared D21 executor, wraps each round-trip inside the
    // adapter's chunk loop.
    Embed(ctx context.Context, req *EmbedRequest) *EmbedRoundTrip
    Identity() Identity // labels Error.Provider/Error.Auth (D9); ProviderOpenAI | ProviderGoogle
}

// EmbedRequest is one Embed call's input, built by the Embedder from its fields.
// The adapter translates it to its wire format. Dimensions == 0 means native;
// a non-zero value is passed to the provider verbatim (the Embedder verifies
// returned lengths, D18 — the adapter does not range-check it).
type EmbedRequest struct {
    Model      string
    Inputs     []string
    Role       InputType
    Dimensions int
    Retry      RetryPolicy
}

// EmbedRoundTrip is the assembled low-level result the Embedder lifts into a
// consumer EmbedResult. Vectors are already unit-normalized and in input order;
// Usage is summed across the request's chunks.
type EmbedRoundTrip struct { /* unexported */ }
func (r *EmbedRoundTrip) Vectors() [][]float32
func (r *EmbedRoundTrip) Usage() EmbeddingUsage
func (r *EmbedRoundTrip) Warnings() []Warning
func (r *EmbedRoundTrip) Err() error
```

Each embeddings-capable sub-package exposes a constructor typed to the embeddings SPI, following the uniform credential pattern of D5 (typed credential argument from the package's closed set) and reusing the same `WithBaseURL`/`WithHTTPClient` options. Only OpenAI and Google have one — embeddings are a deliberate subset (product):

```go
func openai.NewEmbedder(cred openai.Credential, opts ...Option) agentkit.EmbeddingProvider // /v1/embeddings, bearer; APIKey only (the subscription credential is chat-only, D25 — passing it constructs, and Embed rejects it, D38)
func google.NewEmbedder(cred google.Credential, opts ...Option) agentkit.EmbeddingProvider // :batchEmbedContents, x-goog-api-key (Gemini API key, NOT Vertex/OAuth)
```

**Adapter implementation seam.** OpenAI's `/v1/embeddings` shape is shared with any future OpenAI-compatible embedding provider through an **`internal/openaicompat` embeddings variant** (parallel to the chat one, never public); Google's `embedContent`/`batchEmbedContents` shape, `task_type`, and normalization fix-up need their **own** adapter. Both reuse the existing rails verbatim: `internal/httpx` for the HTTP call, the D7 `Error` taxonomy + classification, and — wrapping each chunk round-trip — the shared `internal/retry` executor (D21) under the D11 `RetryPolicy`.

Settled choices:
- **A distinct exported `EmbeddingProvider` SPI, not a widened `Provider`.** Unchanged reasoning: one interface would saddle each side with the other's dead methods.
- **Identity, not a name string — the same split as the chat SPI (D9).** Embeddings report `Identity{Provider, Auth}` for the same reason chat does, and applying it to only one SPI would leave two vocabularies inside the module. It also resolves an asymmetry the previous shape carried: the `openai` chat provider labelled itself `openai.apikey` while its embedding sibling labelled itself bare `openai`, so the same package answered the same question two ways. Under `Identity` both report `{ProviderOpenAI, AuthAPIKey}` — and `AuthAPIKey` is the only mode an embedder can report, since the subscription backend serves no embeddings and that credential is rejected by `Embed` (D38).
- **A parallel `NewEmbedder` constructor, leaving the chat `New` (D5) untouched.** "OpenAI and Google only" stays structural (no `anthropic.NewEmbedder`/`xai.NewEmbedder`/`zai.NewEmbedder`/`openrouter.NewEmbedder` exists to call). The credential is the same per-package closed type as chat's (D5); for `openai`, only `APIKey` is embeddings-capable — the subscription backend serves no embeddings, so a `Subscription` credential constructs and is rejected by `Embed`, the operation that can actually judge it (D38). xAI is chat-only (research §20.6).
- **No `Pricing` method, no model gate, no spec table.** The former per-model `Specs` gate (dimension ranges, model validity before the call) is model knowledge, evicted per D5. The adapter passes `Model` and `Dimensions` through verbatim; the vendor rejects what it doesn't accept (typed error), and the Embedder's post-return length check (D18) enforces the dimension promise without a table. Cost is the Embedder's concern (D18/D20); the adapter only reports usage.
- **The adapter owns the whole call, including chunking — there is no separate orchestrator.** Unchanged.
- **Guarantee 1 — always L2-normalize, client-side, uniformly.** Unchanged: mandatory for `gemini-embedding-001` below native dimension (research §12.2), an idempotent no-op elsewhere.
- **Guarantee 2 — batch auto-chunk + order-preserving reassembly.** Unchanged: split across the provider's per-call item ceiling, one round-trip per chunk, concatenate in input order, sum `EmbeddingUsage`.
- **Guarantee 3 — fail-loud on over-length input.** Unchanged: Google gets `autoTruncate:false` so over-length errors instead of truncating; OpenAI already 400s; both map to `ErrContextLength`. No client-side token counting.
- **`InputType` lowering is per-adapter.** Unchanged: Google maps `InputQuery → RETRIEVAL_QUERY`, `InputDocument → RETRIEVAL_DOCUMENT`, `InputUnspecified → omit`; OpenAI ignores the role entirely.
- **Retry reuses D11 (executed by the shared D21 executor) with no first-byte rule.** Unchanged: each chunk round-trip retried under `Embedder.Retry` for retryable categories; embeddings are non-streaming and idempotent.

**Rejected.**
- *Registry-gated model validity and per-model spec tables in the adapter* — the previous design; model knowledge evicted per D5 (day-one models, dumb layer). The vendor judges; the Embedder's post-return check covers the dimension promise.
- *One `Provider` interface covering both chat and embeddings* — unchanged rejection.
- *Reusing the chat `New` to return a value that also embeds* — unchanged rejection; the subset stays structural.
- *A root embeddings orchestrator layered above a per-chunk adapter* — unchanged rejection.
- *Trusting providers to normalize* — unchanged rejection (Google doesn't below native).
- *Letting Google silently truncate* — unchanged rejection.
- *Client-side token counting to pre-reject over-length input* — unchanged rejection.

**Verification.**
- R-D7QO-K6RZ — each embedding provider's `NewEmbedder(cred, opts...)` accepts its package's credential type, returns a value assignable to `Embedder.Provider`, and an `Embed` against it issues a correctly-authenticated request to that provider's embeddings endpoint (OpenAI `Authorization: Bearer` → `/v1/embeddings`; Google `x-goog-api-key` → `:batchEmbedContents`) and decodes one vector per input from the served fixture.
- R-LL8D-N2OD — each embedding provider's `Identity()` returns its package id with `AuthAPIKey`: `openai.NewEmbedder(openai.APIKey(k))` reports `{ProviderOpenAI, AuthAPIKey}` — the identical `ProviderID` its chat sibling reports, closing the bare-`openai`-versus-`openai.apikey` asymmetry — and `google.NewEmbedder` reports `{ProviderGoogle, AuthAPIKey}`. An `*Error` from an embed round-trip carries those two fields (R-LMGA-0UF2's shape), and no embedder returns the zero `AuthMode`.
- R-YHYV-Q0IR — every vector returned from `Embed` is unit-length within float tolerance, for both providers and including a Google request with `Dimensions` set below native (which the provider returns un-normalized) — AgentKit's client-side L2-normalization, not the provider's.
- R-YJ6S-3S9G — a batch larger than the provider's per-call item limit is split into multiple round-trips and reassembled so the result has exactly `len(inputs)` vectors in input order, with `EmbeddingUsage` summed across the chunks (asserted against a fake server that records the chunk count).
- R-YKEO-HK05 — an over-length single input surfaces a provider `*Error` with `Category == ErrContextLength` (the Google adapter sending `autoTruncate:false` so the provider errors rather than truncating; OpenAI's 400 mapping likewise), and no silently-truncated vector is ever returned.
- R-YLMK-VBQU — the Google adapter lowers `InputQuery`/`InputDocument`/`InputUnspecified` to `task_type: RETRIEVAL_QUERY`/`RETRIEVAL_DOCUMENT`/omitted respectively on the wire, while the OpenAI adapter emits no task/role field for any `InputType` (asserted on the recorded request body).
- R-YO2D-MV88 — a retryable-category failure on an embed round-trip (including on one chunk of a multi-chunk batch) is retried under `Embedder.Retry` per the D11 policy — with the injected clock asserting the attempt count — and a non-retryable-category failure is not retried; the no-retry-after-first-byte rule does not apply (embeddings are non-streaming and idempotent).
