# Decision 36 — `toolkit`: `WebSearch` — Brave-backed web search

**Decision.** The `toolkit` package gains a `WebSearch` tool: a thin, direct client of the
Brave Search API's web-search endpoint (research §19) exposed as a ready-made
`agentkit.Tool`, so every AgentKit consumer hands its agents the same search capability
instead of wiring an MCP server or writing its own client.

```go
// package toolkit

// BraveAPIKey is the toolkit's closed credential type for Brave Search.
type BraveAPIKey string

// WebSearch returns a tool that searches the web via the Brave Search API.
// An absent key constructs normally and fails when the tool is called (D38).
// It honors WithBaseURL and WithHTTPClient (D27); other options are ignored.
func WebSearch(key BraveAPIKey, opts ...Option) agentkit.Tool
```

Settled choices:

- **Credential is passed in, typed, per the Conventions credential rule.** The consumer
  supplies the Brave key explicitly (conventionally read from `BRAVE_API_KEY` at its
  composition root); the library reads no environment. The parameter is the package's own
  closed `BraveAPIKey` type rather than a bare `string`, matching D5's rule across the
  fleet. An **empty key constructs normally**; the call reports the missing credential —
  D38 owns that behavior and this Decision does not restate it.
- **Not part of `All`.** `All(root)` remains exactly the six local coding tools (D27);
  `WebSearch` requires a credential the consumer must consciously supply, so it is composed
  in explicitly:
  `append(toolkit.All(root), toolkit.WebSearch(toolkit.BraveAPIKey(key)), toolkit.WebFetch())`.
- **The endpoint root is the consumer's to set.** Brave's `https://api.search.brave.com` is
  an unexported package **constant** and the default; `WithBaseURL` (D27) replaces it, so a
  consumer can drive the tool against a stand-in server in its own suite, or a proxy in
  front of the real service. A trailing slash on the supplied value is trimmed
  (`strings.TrimRight(baseURL, "/")`), matching the six provider packages, so
  `http://127.0.0.1:8080/` and `http://127.0.0.1:8080` behave identically. The path
  `/res/v1/web/search` is appended to whatever root is in force and is never configurable —
  it is part of the Brave contract this tool implements, not a deployment detail.
  A **supplied-but-empty** base URL is a configuration mistake, not a request against a
  relative URL: the call fails with `agentkit.ErrInvalidConfig` naming the base URL, and
  issues no HTTP request. The check sits **after** D38's key check, so a caller missing both
  hears about the credential first, exactly as `ocr` orders the same pair.
- **The HTTP client is the consumer's to supply.** The request is carried by the client
  given via `WithHTTPClient` (D27), defaulting to `http.DefaultClient` through
  `internal/httpx.Client` like every other network package in the module. That one seam
  carries every transport concern at once — timeout, proxy, TLS trust, redirect policy,
  recording — so the package mints no scalar option shadowing a field the client already
  has, and there is no precedence rule between overlapping knobs to specify.
- **The wire.** One request per call: `GET <base>/res/v1/web/search`
  with `X-Subscription-Token` and `Accept: application/json`, parameters on the query
  string, `text_decorations=0` always pinned so snippets arrive clean. Raw `net/http`, per
  D12. A **10-second** deadline bounds the request on top of the caller's context, and
  applies whatever client is in force — so an injected client with a shorter timeout
  shortens the bound and one with no timeout is still bounded, while a consumer needing
  *longer* than ten seconds against its own gateway is the case this deliberately does not
  serve. No retry: any failure — including 429 — returns as a tool error the agent can read and
  act on (wait, narrow, retry), carrying the HTTP status, Brave's `error.detail` when the
  body parses as Brave's `ErrorResponse` shape, and the `Retry-After` header value when
  present. Note Brave signals an invalid key as HTTP 422 `SUBSCRIPTION_TOKEN_INVALID`, not
  401 (research §19.4) — the error text passes Brave's detail through rather than guessing
  a category from the status class.
- **The parameter surface mirrors Brave's own** (names, semantics, defaults, and
  description text adapted from research §19.2), in the toolkit's snake_case field style:

```go
type webSearchInput struct {
	Query         string   `json:"query"`                    // required; max 400 chars, 50 words
	Count         int      `json:"count,omitempty"`          // 1–20, default 10
	Offset        int      `json:"offset,omitempty"`         // 0–9, default 0
	Country       string   `json:"country,omitempty"`        // 2-letter code or ALL, default US
	SearchLang    string   `json:"search_lang,omitempty"`    // default en
	Freshness     string   `json:"freshness,omitempty"`      // pd|pw|pm|py|YYYY-MM-DDtoYYYY-MM-DD
	Safesearch    string   `json:"safesearch,omitempty"`     // off|moderate|strict, default moderate
	ResultFilter  []string `json:"result_filter,omitempty"`  // e.g. ["web","news"]; joined with commas
	ExtraSnippets bool     `json:"extra_snippets,omitempty"` // up to 5 extra excerpts per result
	Spellcheck    *bool    `json:"spellcheck,omitempty"`     // default true
}
```

  Only supplied fields reach the query string (`q` maps from `query`; everything else keeps
  its name); Brave's own defaults apply otherwise, and Brave's own validation errors pass
  through for out-of-range values. `summary`, `goggles`, `ui_lang`, `units`, and
  `text_decorations` are deliberately not exposed.
- **Output is the useful subset, as JSON.** The tool returns a JSON object holding only
  what an agent reads: `web` as a list of `{title, url, description, extra_snippets?}`,
  and — only when present in Brave's response — sibling sections (`news`, `videos`,
  `discussions`, `faq`, `infobox`) reduced the same way. Brave's ranking (`mixed`), query
  metadata, and per-result decoration fields (`meta_url`, `profile`, …) are dropped. The
  result passes through the toolkit's uniform 30k `capOutput` (D27).
- **Test seam — the public one, and only that one.** The unit suite drives the tool against
  `httptest` servers replaying the measured payloads of research §19, reaching them through
  `WithBaseURL` and bounding the hanging-server case through `WithHTTPClient`, exactly as an
  outside consumer would. The package keeps **no** mutable base-URL or timeout variable for
  tests to swap: a seam the library's own suite declines to use is weak evidence the seam
  works, and mutable package state is what would stop these tests running in parallel. Per
  the settled test plan, the recorded research is the contract's ground truth — the normal
  suite makes **no live Brave calls** and there are no integration-tagged tests for this
  tool.

**Rejected.**
- *Wrapping the Brave MCP server* — an external Node dependency per consumer, and the
  whole point of shipping the tool is that consumers stop depending on it.
- *Self-sourcing the key from `BRAVE_API_KEY`* — would be the library's first environment
  read; the Conventions credential rule (explicit supply) wins, as with every provider.
- *A retry policy (`internal/retry`)* — the account is paid (sustained 429s are not an
  expected condition), and the consumer of a tool error is an agent that can decide to
  wait and reissue; grinding inside the tool hides the signal.
- *Mirroring all fifteen Brave parameters* — `summary` feeds a summarizer tool we don't
  ship, `goggles` is niche re-ranking, `ui_lang`/`units` shape display strings we drop,
  and `text_decorations` is pinned off; exposing them is surface without behavior.
- *The specialized sibling endpoints (news/images/videos/local/summarizer)* — the web
  endpoint already returns news/video/discussion sections; a sibling tool is a later
  Decision if a consumer ever needs one.
- *A per-call `timeout_seconds` parameter on the schema, as `WebFetch` (D37) carries* — the
  bound is a property of the deployment, which the consumer knows and the model does not,
  and an agent-visible knob is surface a confused model can misuse. The consumer sets it on
  the client it injects.
- *A scalar `WithTimeout(d)` option* — re-argued here and lost. Timeout, proxy, TLS trust,
  redirect policy, and instrumentation are one concern, how the request is carried, and
  `*http.Client` is the single object that already expresses all of them. A scalar shadowing
  one of its fields commits the package to adding the next scalar the first time someone
  needs a proxy, and forces a precedence rule the moment both are set.
- *A hard-coded, unreachable endpoint (the prior choice here)* — it made the tool's own
  suite reach inside the package to swap a variable no consumer could touch, which left
  every consumer unable to prove its search wiring works end to end. A consumer's harness
  should be able to drive this tool to a real success against a server it controls.
- *A configurable backend client object (`NewBrave(key, opts...)`) handed to `WebSearch`,
  mirroring `ocr.New` + `ocr.Tool`* — D27 rejects it for the package; there is no Brave
  client here worth naming, only a base URL and a transport.

**Verification.**
- R-1FSS-YX2G — the tool's declared name is `WebSearch`; its schema's `required` set is exactly `["query"]`; its properties are exactly `query`, `count`, `offset`, `country`, `search_lang`, `freshness`, `safesearch`, `result_filter`, `extra_snippets`, `spellcheck`, each carrying a non-empty `description`.
- R-1H0P-COT5 — a call sends one `GET` to `/res/v1/web/search` carrying the constructed key in `X-Subscription-Token`, the query as `q`, `text_decorations=0`, and each supplied optional parameter under its Brave name (`result_filter` comma-joined); parameters the caller omitted are absent from the query string.
- R-1I8L-QGJU — fed the measured Brave 200 payload (research §19.3), the tool returns JSON whose `web` entries are exactly `{title, url, description, extra_snippets?}`, whose optional sections appear only when the payload contains them, and which contains no `mixed`, `query`-metadata, `meta_url`, or `profile` content.
- R-1JGI-48AJ — a non-2xx Brave response yields a tool error naming the HTTP status and Brave's `error.detail` when the body is an `ErrorResponse` (measured 422 shapes, research §19.4), and including the `Retry-After` value when that header is present (429).
- R-1KOE-I018 — against a server that never responds, the call fails with a timeout error instead of hanging (the request is bounded even under an unbounded caller context).
- R-1D5U-0OIN — a tool built with `WithBaseURL(srv.URL)` sends its request to that server and to no other host, and the server observes the path `/res/v1/web/search`; a tool built with **no** options sends to `https://api.search.brave.com`. Supplying `srv.URL+"/"` produces a byte-identical request URL to supplying `srv.URL`. A tool that ignores the option, or that lets the option replace the endpoint path, fails this.
- R-1EDQ-EG9C — with a non-empty key, `WithBaseURL("")` makes the call fail with an error wrapping `agentkit.ErrInvalidConfig` whose message names the base URL, and **not** `ErrMissingCredential`, with no HTTP request issued (recorded request count = 0). With **both** the key and the base URL empty, the error wraps `ErrMissingCredential` instead — the key is reported first. One sentinel serving both conditions, or the opposite check order, fails this.
- R-1FLM-S801 — a tool built with `WithHTTPClient(c)`, where `c` carries a custom `Transport`, has its request carried by that transport (the transport records exactly one round trip carrying `X-Subscription-Token`), and `http.DefaultClient` is not used. A tool built with no options routes through `internal/httpx.Client(nil)`, i.e. `http.DefaultClient`.
- R-1GTJ-5ZQQ — the injected client shortens the bound but cannot lengthen it. Against a server that never responds, `WithHTTPClient(&http.Client{Timeout: 50 * time.Millisecond})` fails with a timeout in well under one second. Against a responsive server reached with `WithHTTPClient(&http.Client{Timeout: 0})` (no client-side timeout), the handler observes a request whose context **has** a deadline, no later than ten seconds out — so the tool's own deadline still applies to an injected client that sets none. A tool that drops its deadline when a client is injected fails this; asserting only the fast case does not satisfy it.
