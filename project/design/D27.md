# Decision 27 — The `toolkit` subpackage: standard coding tools, root confinement, output cap

**Decision.** A new leaf subpackage `github.com/ikigenba/agentkit/toolkit` (package `toolkit`) ships the standard local coding tool set — `Bash`, `Read`, `Write`, `Edit`, `Glob`, `Grep` — as ready-made `agentkit.Tool` values, so consumers (agent-repl, the prompts service, ralph, any agent harness) stop re-implementing the same six tools (research §16). The package name is `toolkit`, not `tools`, because both existing consumers already have an internal package named `tools` and would otherwise alias every import.

```go
// package toolkit

// Option adjusts an optional setting on a toolkit tool. Each constructor
// honors the options that apply to it and ignores the rest; the doc comment
// on every constructor names which it honors.
type Option func(*config)

func Bash(root string, opts ...Option) agentkit.Tool
func Read(root string, opts ...Option) agentkit.Tool
func Write(root string, opts ...Option) agentkit.Tool
func Edit(root string, opts ...Option) agentkit.Tool
func Glob(root string, opts ...Option) agentkit.Tool
func Grep(root string, opts ...Option) agentkit.Tool

// WebSearch (D36) honors WithBaseURL and WithHTTPClient;
// WebFetch (D37) honors WithHTTPClient. The six local tools honor neither.
func WithBaseURL(baseURL string) Option
func WithHTTPClient(client *http.Client) Option

// All returns the six local tools above, in exactly that order.
func All(root string) []agentkit.Tool
```

Settled choices:

- **Per-tool constructors plus `All`.** Consumers wanting the whole local set take `All(root)`; a consumer composing its own set (the prompts service keeps service-specific extras alongside) takes individual constructors. `All` is a bundle, not a tool constructor, and takes no options.
- **One constructor shape across the package.** Every tool constructor reads the same way: its required arguments positionally, then `opts ...Option`. There is exactly one `Option` type for the package, and it is the only mechanism for an optional setting — no per-tool option types, no configurable backend object, no options struct. Which options a given constructor honors differs, and its doc comment says so; the *shape* never differs. A tool that honors no option today still takes the variadic, so the package has one signature to learn rather than one per tool.
- **The option set is exactly what the capabilities require.** Two options exist: `WithBaseURL`, because a consumer must be able to point `WebSearch` somewhere other than Brave (D36), and `WithHTTPClient`, because every network call in the module goes through a client the consumer can supply. Nothing else is minted speculatively; an option arrives when a settled capability needs it.
- **`root` is the tool root.** Every constructor takes the same `root string`: the directory file paths resolve against and `Bash`'s working directory. `root == ""` means the process working directory. Relative inputs join the root; absolute inputs are permitted when they resolve inside it.
- **Hard confinement for the file tools.** `Read`, `Write`, `Edit`, `Glob`, and `Grep` reject any path that resolves outside the root — including escapes through symlinks: the existing prefix of the candidate path is resolved through `EvalSymlinks` before the containment check (the prompts-service `confinePath` approach, research §16.1). A rejected path errors naming the escaping input. **`Bash` is deliberately not confined** — it only gets cwd = root — so the package documentation states plainly that confinement is protection against accidents, not a security sandbox.
- **Uniform output cap.** Every tool result is capped at **30,000 characters** (an unexported package constant, matching the field-proven Claude Code default, research §16.2). Longer content is cut at the cap with an explicit trailing marker naming shown and total sizes, e.g. `[output truncated: showing first 30000 of 348192 characters]`. The model pages via `Read` offset/limit or narrows its search; nothing is silently dropped without the marker.
- **Tool names are TitleCase** (`Bash`, `Read`, …) and input fields use the `file_path`/`old_string`-style snake_case models are trained on (research §16.2); the exact per-tool schemas are D28–D30's contracts.
- Tools are built with the existing `agentkit.NewTool` generic constructor (D4); the toolkit adds no new registration machinery.
- **The package also hosts the web tools — outside `All`.** `WebSearch` (D36) and `WebFetch` (D37) live in `toolkit` too, so every consumer draws one standard toolset, but they are network tools (one needs a credential) and are **not** part of `All(root)`, whose contract stays exactly the six local, root-confined coding tools above. Consumers compose them in explicitly: `append(toolkit.All(root), toolkit.WebSearch(toolkit.BraveAPIKey(key)), toolkit.WebFetch())`, adding options where they want them: `toolkit.WebSearch(key, toolkit.WithBaseURL(stub.URL), toolkit.WithHTTPClient(c))`. The confinement and cap conventions of this Decision apply to them where they make sense (the 30k output cap does; root confinement is meaningless for the network). `WebSearch`'s credential is a typed `BraveAPIKey` from this package's closed set and an absent one fails at the call, not at construction — D38 owns both.

**Rejected.**
- *A standalone module shared by agent-repl and ralph* — a third repo and version-pinning ceremony for ~a few hundred lines; agentkit is the natural home and already the shared dependency of every consumer.
- *Package name `tools`* — collides with both existing consumers' internal `tools` packages, forcing aliases at every adoption site.
- *Resolution-base-only roots (agent-repl style)* — an unattended agent writing through `../` or a stray symlink is exactly the accident confinement exists to stop; prompts can only adopt the toolkit if confinement is at least as strong as what it has.
- *A configurable output cap* — no settled capability needs one; the 30,000-character constant serves every current consumer, and an option exists here only when a capability requires it.
- *An options struct passed by value* — a variadic `Option` keeps the ordinary call (`toolkit.Read(root)`) unchanged and lets a caller name only what it is setting; a struct forces every call site to mention a type whose fields are almost always zero.
- *Per-tool option types (`SearchOption`, `FetchOption`) so an inapplicable option is a compile error* — buys compile-time rejection of `WebFetch(WithBaseURL(u))` at the cost of two types, a split spelling of `WithHTTPClient`, and a package whose tools no longer read alike. Uniformity of shape across the nine constructors is worth more than catching one nonsensical call that no consumer has reason to write; the constructor doc comment names what it honors.
- *A configurable backend object (`NewBrave(key, opts...)` handed to `WebSearch`), mirroring `ocr.New` + `ocr.Tool`* — correct for `ocr`, which has a genuine client with a cache and a transcript to own, and wrong here: it invents an object for `WebSearch` alone, leaves `WebFetch` with nowhere to put its client, and makes one tool constructor read unlike the other eight.
- *`doublestar` (or any new module) for globbing* — external dependencies need explicit operator approval (Conventions); stdlib suffices (D30).

**Verification.**
- R-LQ1Y-XASG — `All(root)` returns exactly six tools whose declared names are `Bash`, `Read`, `Write`, `Edit`, `Glob`, `Grep`, in that order.
- R-LR9V-B2J5 — each per-tool constructor returns a tool whose declared name matches its constructor (`Bash(root)` → `Bash`, … for all six).
- R-Y446-A6MP — every property of every toolkit tool's schema carries a non-empty `description`, and each tool's `required` set names exactly its mandatory parameters (`Bash` requires `command` and not `timeout`; `Read`, `Write`, `Edit` require `file_path`; `Glob` and `Grep` require `pattern`); a tool with an empty `required` array or an undescribed property fails this.
- R-LSHR-OU9U — for each of `Read`, `Write`, `Edit`, `Glob`, `Grep`: a relative path that resolves outside the root (e.g. `../escape`) is rejected with an error and no filesystem effect outside the root occurs.
- R-LTPO-2M0J — a path that reaches outside the root **through a symlink inside the root** is rejected by the file tools, even though its literal join stays under the root.
- R-LUXK-GDR8 — with `root == ""`, file tools resolve relative paths against the process working directory (a file created in a temp cwd is readable by name).
- R-LW5G-U5HX — a tool result whose content exceeds 30,000 characters is returned cut at 30,000 characters with a trailing truncation marker naming the shown count and the total size; content at or under the cap is returned unmarked.
