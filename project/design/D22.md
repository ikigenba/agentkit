# Decision 22 — Per-provider schema rendering at the adapter boundary

**Decision.** Each provider adapter **renders** a canonical tool schema (D34) into its own wire dialect. Rendering is total and infallible by construction: because the canonical subset admits only constructs every dialect can express, and membership is enforced at the `Send` gate before any adapter runs, an adapter never encounters a construct it cannot carry. There is therefore **no residue, no lossy-schema warning, and no capability interface** — the superseded `ToolSchemaTranslator` and `WarnToolSchemaLossy` are deleted, and root holds no per-provider schema knowledge beyond the subset itself.

Rendering is a pure function of the canonical schema, private to the adapter, applied at request-build time:

```go
// Each adapter owns an unexported renderer. No shared interface: rendering
// happens where the wire format is already known, and root never sees a
// dialect-specific schema shape.
//
//   anthropic: func renderSchema(json.RawMessage) map[string]any
//   openai:    func renderSchema(json.RawMessage) map[string]any
//   google:    func renderSchema(json.RawMessage) map[string]any
```

Settled choices:
- **No adapter sends a strict flag.** Anthropic and OpenAI both receive tools with `strict` absent, and Gemini has no such mode, so the wire is uniformly non-strict. Strict is not rationed or conditionally applied: it is gone. Research §18.6 is the forcing fact. Anthropic caps a request at **20 strict tools** and at **24 optional parameters aggregated across all strict tools**, so a library that marks tools strict is correct only below a tool count it does not control, and above it the failure is a hard 400 (`Too many strict tools (146)`, observed in production) rather than a degradation. Deferring a tool's definition does not help, because the grammar compiles from the full toolset. A guarantee that evaporates at an inventory size AgentKit cannot see is not a guarantee.
- **Enforcement moved to AgentKit and became provider-independent.** What strict bought (a declared constraint is actually honored) is now delivered by D39's runtime argument validator, which checks the model's arguments against the canonical schema before any tool is invoked, on every provider and for every tool source. This is strictly more than strict ever covered: Gemini never had strict at all, and OpenAI strict silently tolerates several keywords it does not act on. The contract is now AgentKit's own rather than borrowed from whichever provider happens to enforce.
- **Research §18.4 still binds, and it is why the subset does not widen.** Non-strict providers accept every construct strict rejects and honor none of them. Strict rejection is therefore read as evidence of non-honoring: a construct Anthropic strict refuses stays out of the D34 subset regardless of the wire flag, because dropping the flag changed what the provider *validates*, not what it *understands*. Removing strict is not a licence to widen the subset, and D34's membership list is unchanged.
- **`additionalProperties` is injected by the adapter, at every object level.** The renderer walks the whole schema, not just the root. Under non-strict this is no longer a provider-enforced constraint; it is kept because it is a truthful declaration to the model of what the tool accepts, and closed-object is now genuinely enforced by D39's validator, which rejects unknown properties. Dropping it would leave the wire schema silent about invented parameters while AgentKit refuses them, which is exactly the divergence between the model's picture and our enforcement that this design avoids. Gemini receives no `additionalProperties` at all, since the key is a hard 400 there and a closed object is Gemini's only behavior anyway.
- **Optionality is rendered honestly on every provider.** The canonical form states optionality by omitting a property from `required` (D4), and all three adapters now take that verbatim. OpenAI's former rewrite (move every property into `required`, make the omitted ones nullable) existed only to satisfy strict's structural rule that no property may be optional (research §18.2), and dies with strict. Required-but-nullable is a worse signal than plain-optional: it tells the model to decide about a field and pass an explicit null where the truth is that it may omit it. Rendering optionality the same way everywhere also collapses the three renderers toward one shape, which keeps the construct-complete fixtures honest and keeps the wire form close to the canonical form the validator checks against.
- **Nullability has two spellings, one meaning.** Anthropic and OpenAI take the `"type": ["T","null"]` union; Gemini rejects type unions and takes `"type": "T", "nullable": true`. The union is still rendered where a schema authors one; it is simply no longer manufactured out of optionality.
- **`oneOf` is rewritten to `anyOf` by every renderer, not only Google's.** Anthropic and OpenAI both reject `oneOf` (research §18.2, §18.3); the subset admits it (D34) only because this rewrite is universal and mechanical.
- **Fidelity is tested with one construct-complete fixture.** Each renderer's suite feeds it a canonical schema exercising every subset construct once and asserts each construct is present in the recorded request, in dialect form — so a renderer that silently drops a key cannot pass, and a future subset widening fails the fixture until the renderers carry it.
- **Google's renderer is an allowlist, never a denylist.** Gemini 400s on any key that is not a proto field (research §18.1), so an unrecognized construct must be structurally unreachable rather than filtered out. It also inlines `$ref` against `$defs`, maps `oneOf` to `anyOf`, rewrites `const: v` to `enum: [v]`, and emits no `$schema`.
- **Anthropic and OpenAI stop receiving `$schema` and `$defs` by accident.** The superseded design passed the derived schema through verbatim, so the reflector's `$schema` URL and `$defs` blocks reached three providers untouched. Rendering is now explicit for every provider; nothing arrives because nobody filtered it.
- **Deterministic tool ordering is unchanged** — adapters sort by name at send time for cache-prefix stability (D10), independent of rendering.
- **The compat providers inherit OpenAI's renderer.** `zai` and `openrouter` delegate through `internal/openaicompat`, so they render exactly as OpenAI does. Neither publishes a keyword contract of its own and OpenRouter's effective dialect depends on the routed upstream (research §18.5), so emitting the narrowest well-defined form is the only defensible choice.
- **The wire change is proven against the real providers, not only fixtures.** A recorded server accepts whatever it is handed, so a fixture asserting the absence of a `strict` key confirms a field changed and cannot confirm the provider stops rejecting us. Two Verification ids drive live calls: one attaching well over 20 tools to Anthropic, one sending a partial `required` array to OpenAI. The second closes a real evidence gap, since research §18.4 measured non-strict acceptance of `pattern` and `minimum` behaviourally but never probed the `required` rule.

**Rejected.**
- *Keeping strict below the cap and dropping it above* — the tool count is a property of the consumer's configuration, so behavior would flip between runs of the same program as tools are attached, and the 24-optional-parameter cap bites well below 20 tools anyway. Two enforcement regimes selected by an invisible threshold is worse than one regime.
- *Per-tool opt-in strict metadata* — the same flakiness with a configuration surface bolted on, and it would let a consumer construct a request that fails only once a fifteenth tool is registered. If strict returns it must be a whole-request property with an explicit failure when it cannot apply, not a per-tool hint.
- *Keeping strict on OpenAI, where no cap applies* — buys enforcement AgentKit now performs itself, at the cost of a provider-dependent contract: the same wrong tool argument would be unsamplable on OpenAI and a corrected retry on Anthropic. Uniformity across providers is the product promise; a redundant belt that only some providers wear is not worth the divergence, and it would keep OpenAI's structural rules distorting the rendered schema.
- *Widening the D34 subset now that no provider validates it* — §18.4 says an accepted keyword is an ignored keyword, so a construct Gemini's parser cannot carry would have to be dropped by the renderer, reintroducing the silent weakening D34 exists to forbid. A widening argued from "AgentKit enforces it anyway" is a real argument and a separate Decision, requiring its own measurement.
- *A `ToolSchemaTranslator` capability interface with residue reporting* — the model this Decision replaces. It could only describe the configured provider, so it could not enforce uniformity (D34), and its residue warning fired on every typed tool because the derived schema always carried `additionalProperties: false`. Deleted rather than repaired.
- *A shared rendering interface in root* — would put dialect-shaped schema types in a provider-agnostic package for no gain; each adapter already knows its own wire format, and the renderers share no logic worth abstracting.
- *Rendering that can fail* — an adapter returning an error would imply the gate let something through, which would be the real bug. Rendering is total by construction, and a construct that cannot be rendered is a D34 subset defect, not a runtime condition.

**Verification.**
- R-80QS-7XKB — the Anthropic adapter sends each tool with **no `strict` key present at all** in the tool object (absent, not `false`), and an `input_schema` carrying `"additionalProperties": false` on the root object **and on every nested object**, with optional properties omitted from `required`, and with no `$schema` or `$defs` key present; a renderer that emits `strict` in any form, or that sets `additionalProperties` only at the root, fails this.
- R-836K-ZH1P — the OpenAI adapter sends each tool with **no `strict` key present at all**, and `parameters` in which a property that is optional in the canonical schema is **omitted from `required`** and rendered with its plain canonical type (not a nullable union), with `"additionalProperties": false` on every object and no `$schema` or `$defs`; the identical tool payload results through `internal/openaicompat` for `zai` and `openrouter`. A renderer that still moves every property into `required`, or that still manufactures a nullable union out of an optional property, fails this.
- R-XVKV-LSFU — the Google adapter sends `parameters` containing **no** `additionalProperties`, `$schema`, `$defs` or `$ref` key at any depth, with `$ref` resolved by inlining its target, `oneOf` emitted as `anyOf`, `const: v` emitted as `enum: [v]`, and a nullable property emitted as a single `type` plus `nullable: true` rather than a type union; a surviving `$ref` or a type union fails this.
- R-2UV8-RBKS — the Anthropic renderer, fed a canonical schema exercising every subset construct (nested object, array `items`, string `enum`, `const`, `anyOf`, `oneOf`, an inlined `$ref`/`$defs`, `pattern`, `minLength`/`maxLength`, `minItems`, an allowlisted `format`, `default`, `title`, `description`, a nullable type union, and a mixed required/optional property set), records a request in which every construct is present: the constraint keys verbatim, `oneOf` emitted as `anyOf`, the nullable union kept as a type list, and `$ref` inlined; a renderer that drops any construct (e.g. `pattern` or `enum`) fails this.
- R-84EH-D8SE — the OpenAI renderer, fed the same construct-complete schema, records every construct present modulo its two remaining rewrites (`oneOf` emitted as `anyOf`, `$ref` inlined), with `pattern`, `minLength`/`maxLength`, `minItems`, `format`, `enum`, `const`, `default`, `title` carried verbatim, the authored nullable union kept as a type list, and the canonically-optional property **absent from `required` and carrying its plain type**; the identical payload results through `internal/openaicompat` for `zai` and `openrouter`. A renderer that drops a construct, or that reinstates the all-properties-required rewrite, fails this.
- R-2XB1-IV26 — the Google renderer, fed the same construct-complete schema, records every construct in proto form: `oneOf` as `anyOf`, `const` as a one-element `enum`, the nullable union as a single `type` plus `nullable: true`, `$ref` inlined, and `pattern`, `minLength`, `maxLength`, `minItems`, `title`, `default`, `format`, `enum`, `description` all present; a renderer that silently drops one of those keys (as the superseded converter did) fails this.
- R-85MD-R0J3 — **live, against the real Anthropic API** (`integration` build tag, skipped when credentials are absent): a `Send` attaching **more than 20 tools** (at least 30, exercising the count that 400s under strict) completes a turn and returns an assistant message, proving the request was accepted rather than rejected with `Too many strict tools`. A recorded-fixture test cannot substitute: the assertion is that the provider accepts the payload, which only the provider can falsify. A build that reinstates `strict` fails this against the live API while still passing every fixture test.
- R-86UA-4S9S — **live, against the real OpenAI API** (`integration` build tag, skipped when credentials are absent): a `Send` carrying a tool whose schema has a **partial `required` array** (at least one property in `properties` omitted from `required`) completes a turn and returns an assistant message, proving OpenAI's all-properties-required rule is strict-scoped as research §18.2 implies. This is the measurement research §18.4 did not take, so it is verified rather than assumed.
- R-XWSR-ZK6J — the `ToolSchemaTranslator` interface and the `WarnToolSchemaLossy` code are absent from the codebase, and a `Send` carrying tools produces **no** warning whose `Setting` is `"tool_schema"` under any provider, while `Stream.Warnings()` still reports unrelated warnings (forced tool choice, unknown cost) unchanged.
- R-XY0O-DBX8 — every adapter serializes its tools sorted by name, so two `Send` calls with the same tool set supplied in different slice orders produce byte-identical tool payloads, preserving the cache prefix.
