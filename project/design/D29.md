# Decision 29 — `toolkit`: `Bash` semantics

**Decision.** `Bash` runs a shell command from the tool root and reports what happened as **data for the model**, reserving Go errors for the tool itself malfunctioning.

```go
// package toolkit

type bashInput struct {
	Command string `json:"command"`           // required, non-blank
	Timeout int    `json:"timeout,omitempty"` // milliseconds; 0 = the 120000 default
}
```

Settled choices:

- **Execution.** `bash -c <command>` (not `-lc`: sourcing login profiles inside a tool is surprising and environment-dependent), `cmd.Dir` = the D27 root, stdout and stderr combined in arrival order.
- **A nonzero exit is a normal result.** The output is returned with a trailing `[exit status N]` line and a **nil** tool error (the agent-repl contract, research §16.1) — a failing test run is ordinary information an agent works with, and an error-flagged result degrades model recovery. Go errors are reserved for spawn failure (bash missing, bad root) and validation (blank command).
- **Timeout.** Optional `timeout` in milliseconds, defaulting to **120,000** (the Claude Code convention, research §16.2). On expiry — or on context cancellation — the process is killed and the captured output so far is returned as a normal result with an explicit marker reporting the timeout/cancellation.
- **Process-group kill.** The child runs in its own process group (`Setpgid`), and expiry/cancellation kills the **group**, so background children the command spawned die with it — a hung `go test` must not orphan a server that holds the loop's ports.

**Rejected.**
- *Go error on nonzero exit (prompts service)* — flags routine failures as tool malfunctions and trains the model away from reading the output.
- *`bash -lc` (agent-repl)* — login-shell profile sourcing makes tool behavior vary by machine dotfiles.
- *No timeout (both existing implementations)* — one command waiting on stdin hangs an unattended loop forever.
- *Path confinement for Bash* — unenforceable theater; a shell can always reach the whole filesystem. Documented honestly in D27 instead.

**Verification.**
- R-M8CG-NUWV — `Bash` runs the command via `bash -c` with the tool root as working directory and returns combined stdout+stderr (a command writing to both streams yields both, and `pwd` reports the root).
- R-M9KD-1MNK — a command exiting nonzero returns its output plus a trailing `[exit status N]` marker as a normal result (nil tool error).
- R-MAS9-FEE9 — a command exceeding its `timeout` (ms) is killed: the result arrives without waiting for the command, reports the timeout explicitly, and includes output captured before the kill.
- R-MC05-T64Y — the timeout kill takes the whole process group: a background child spawned by the timed-out command is no longer alive after the tool returns.
- R-MD82-6XVN — a blank (empty or whitespace-only) command returns an error without spawning anything.
