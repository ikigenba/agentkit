# Decision 5 — Provider packaging, construction credentials, and free-flow model selection

**Decision.** One sub-package per provider; each package exposes exactly one constructor, uniformly shaped across the fleet: `New(cred Credential, opts ...Option) *Provider`, returning the opaque `agentkit.Provider` handle the consumer assigns to `Conversation.Provider`. The credential is a **typed argument** drawn from a **per-package, closed `Credential` set** — the parameters carry the auth choice; the constructor name never does. The provider layer is a **dumb wire encoder**: endpoint + protocol + credential and nothing else. It holds **no model registry, no pricing table, no reasoning specs, and no exported model constants** — a provider package changes only when its vendor ships a new API shape. Model validity is the vendor's judgment: any model string flows through to the wire verbatim, and an id the vendor rejects surfaces that vendor's typed error.

```go
// package agentkit
//
// Provider is a handle to a configured provider backend — a stateless
// connector (endpoint + protocol + credential). Consumers obtain one from a
// provider sub-package's New and assign it to Conversation.Provider; they do
// not call its methods directly. Its method set is the exported SPI defined in
// Decision 9. It holds no conversation state and no model knowledge; one
// handle can serve many conversations.
type Provider interface{ /* SPI — see Decision 9 */ }
```

The uniform constructor pattern, replicated in every chat provider package — each with its own closed credential set (one member where one mechanism exists):

```go
// Each package declares its own closed Credential interface and members.
// Per-package (not one shared root type) so a cross-package mistake —
// anthropic.New(openai.Subscription(ts)) — is a compile error, never a
// runtime rejection.

anthropic.New(cred anthropic.Credential, opts ...Option) *Provider   // Messages wire; anthropic.APIKey("...")
google.New(cred google.Credential, opts ...Option) *Provider         // generateContent wire; google.APIKey("...")
openai.New(cred openai.Credential, opts ...Option) *Provider         // Responses wire via internal/responses; openai.APIKey("...") | openai.Subscription(ts) — D25
xai.New(cred xai.Credential, opts ...Option) *Provider               // Responses wire via internal/responses; xai.APIKey("...") | xai.Subscription(ts) — D40
zai.New(cred zai.Credential, opts ...Option) *Provider               // Chat-Completions wire via internal/openaicompat; zai.APIKey("...")
openrouter.New(cred openrouter.Credential, opts ...Option) *Provider // Chat-Completions wire via internal/openaicompat; openrouter.APIKey("...") — D24
```

```go
conv := &agentkit.Conversation{Provider: anthropic.New(anthropic.APIKey(key)), Model: "claude-opus-4-8"}
conv.Provider = openrouter.New(openrouter.APIKey(orKey)); conv.Model = "z-ai/glm-5.2"   // switch — any slug, day one
```

Settled choices:
- **Six chat sub-packages: `anthropic`, `google`, `openai`, `xai`, `zai`, `openrouter` — six first-class, named providers.** Shared wires stay internal and unnamed on the public surface: `openai` and `xai` both speak Responses through `internal/responses` (research §2.3, §20); `zai` and `openrouter` both speak Chat Completions through `internal/openaicompat` (research §2.4, §10, §14). Provider first-classness is independent of implementation strategy: each compat-backed provider gets its own package, its own `New`, its own baked-in base URL (`xai`: `https://api.x.ai`; `zai`: `https://api.z.ai/api/paas/v4/`; `openrouter`: `https://openrouter.ai/api/v1/`), and its own `Error.Provider` label — never `"responses"` or `"openaicompat"`. There is no public `responses` or `openaicompat` package. The Go package is `xai`; the id it reports is `x-ai` (D9, D26).
- **One constructor per supported wire; the constructor is the protocol selector.** Each vendor exposes several HTTP APIs; AgentKit supports a deliberate subset — one wire per (vendor, auth mechanism) pair today — and the wire is baked into the constructor, never a runtime parameter and never per-model routing. If a vendor package ever supports a second protocol for the same auth, it gains a qualified sibling constructor (`NewXProvider` — qualifier first, returned noun last); nobody builds one speculatively.
- **Credentials are typed constructor arguments from a per-package closed set.** `New(cred Credential)` everywhere — uniform shape across the fleet even where the set has one member. The credential type selects the auth mechanism (and any auth-implied transport, D25) at compile time; there is no mode string, no auto-detect, no silent fallback. `Conversation` has no `Creds` field; a provider switch is a single assignment carrying its own auth. **Construction is where a credential is supplied, not where it is judged**: `New` accepts an absent credential and constructs, and the round-trip that needs it reports it missing (D38).
- **Free-flow model strings — no registry, no gate.** `Model` stays a `Conversation` string field, passed to the wire verbatim. AgentKit never rejects a model id on its own authority; the vendor judges it and a rejection surfaces as that provider's typed error (D7). There are **no exported model constants** — model discoverability lives in the advisory catalog (D26), which the request path never consults.
- **Providers hold no model knowledge, period.** No pricing (cost is the D16 seam: provider-reported or conversation-supplied), no reasoning specs (values lower by shape, D9, and the vendor judges), no capability metadata (catalog, D26). The eviction is what makes a day-one model run without a library release.
- **Per-provider packaging isolates dependencies** — importing only `anthropic` pulls no Google/OpenAI deps.
- **Functional options per constructor are a supported public surface.** `WithBaseURL(string)` and `WithHTTPClient(*http.Client)` remain: point any provider at an alternate/proxied/self-hosted endpoint (the same OpenAI-compatible wire reaches Fireworks or a self-hosted server via `openrouter`/`zai`-style construction with an overridden base URL), or supply a custom HTTP client. `WithBaseURL` moves the *host*, never the protocol. The default is always correct without options. This is the same seam the D13 test harness points at an `httptest.Server` (R-WKTI-LIIE).

**Rejected.**
- *A curated, closed model set with registry-gated `Send` validity* — the previous design. It made "supported ⇒ priced ⇒ describable" structural, but at the cost AgentKit exists to avoid: a new model could not run until a library release shipped. Free-flow + advisory catalog + the D16 cost seam keeps the conveniences for known models without gating unknown ones.
- *Auth-qualified constructor names (`NewAPIKeyProvider`/`NewSubscriptionProvider`)* — explodes combinatorially the day a second wire appears (name = wire × auth); the identity axis (wire) belongs in the name only when plural, the input axis (credential) in a typed parameter.
- *One shared root `agentkit.Credential` type* — turns cross-package credential misuse into a runtime rejection; per-package closed sets make it a compile error.
- *Per-model wire routing inside a vendor package* — requires a maintained model→API table, re-importing the curation burden for the vendor property that changes most often; the constructor-selects-wire rule keeps the layer dumb.
- *Single package with `agentkit.NewAnthropic(...)`* — forces every consumer to compile in all providers' deps.
- *`Credentials` passed at `Send`* — pushes auth *supply* into the call path; construction-time is the right boundary for supplying one. (Where a credential is *checked* is a separate axis, and the answer there is the opposite one: at the operation, D38.)

**Verification.**
- R-CQO3-7EE9 — each chat provider package's `New(cred Credential, opts...)` returns a value assignable to `Conversation.Provider`, accepts only its own package's credential type(s), and a `Send` against it issues a correctly-authenticated request to that provider's endpoint (per-provider slices; the openai API-key path here, the openai subscription path in D25, the xai paths in D40).
- R-CRVZ-L64Y — `zai.New` and `openrouter.New` issue correctly bearer-authenticated requests to their respective baked-in base URLs via the shared internal OpenAI-compatible adapter; `openai.New` and `xai.New` issue correctly bearer-authenticated Responses requests via the shared internal Responses adapter; the consumer supplies only a credential (no base URL), and neither adapter is exposed as a public package.
- R-CT3V-YXVN — an arbitrary, never-cataloged model string set on `Conversation.Model` reaches the provider's wire request verbatim with no AgentKit-side rejection, and a vendor rejection of an unknown id surfaces as that provider's typed error (per-provider slices).
- R-H65D-HYXH — assigning a new `Provider` (and `Model`) between turns routes the next `Send` to the new backend with `History` intact.
