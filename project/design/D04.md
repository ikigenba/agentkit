# Decision 4 — The tool definition & registration surface

**Decision.** A tool is defined with a single generic constructor at the edge that erases to a non-generic `Tool` interface the orchestration loop holds. The product promise — name, description, input shape, code — maps to `NewTool[In]`. There is **no second constructor**: the schema is always derived from the Go type, never hand-written.

The schema is produced by AgentKit's **own reflector**, targeting the canonical subset (D34) directly. It emits exactly what the subset admits and nothing else — no `$schema`, no `$defs`/`$ref`, no `additionalProperties` (adapter-owned, D22).

```go
// Tool is a registered capability the model may invoke. The Conversation holds
// []Tool; the auto-loop calls them. Non-generic so a heterogeneous set lives in
// one slice.
type Tool interface {
    Name() string
    Description() string
    JSONSchema() json.RawMessage // canonical input schema (D34 subset)
    Call(ctx context.Context, input json.RawMessage) (string, error)
    isTool() // sealed: only NewTool (and the MCP wrapper) produce one
}

// NewTool builds a Tool from a typed input struct. The schema is derived once
// from In by AgentKit's reflector and cached. fn receives the decoded input;
// its string return is the tool result fed back to the model.
//
// NewTool panics if In cannot be mapped into the canonical subset (D34): a
// defective input struct is a programming error, surfaced at construction,
// never deferred to first use.
func NewTool[In any](name, description string, fn func(ctx context.Context, in In) (string, error)) Tool
```

Consumer usage — required-ness comes from the `json` tag, description from the `jsonschema` tag:

```go
type weatherIn struct {
    City  string `json:"city" jsonschema:"description=City name"`
    Units string `json:"units,omitempty" jsonschema:"description=Unit system,enum=metric,enum=imperial"`
}
tool := agentkit.NewTool("get_weather", "Look up current weather",
    func(ctx context.Context, in weatherIn) (string, error) {
        return lookup(in.City), nil
    })
conv.Tools = append(conv.Tools, tool)
```

Settled choices:
- **Generics only at the registration edge, erased into the non-generic `Tool`** — typed `fn(ctx, In)` for the consumer (no manual decode, no manual schema), plain `Tool` for the loop, so `[]Tool` holds a heterogeneous set with no generics in orchestration.
- **Required-ness is derived from the `json` tag, not a separate marker.** A field is **required unless it carries `,omitempty` or is a pointer**. The codebase already encodes intent this way (`toolkit`'s input structs mark optional fields `,omitempty`), and it fails safe: forgetting a marker makes a field required, which the model must supply, rather than silently optional. The superseded opt-in `jsonschema:"required"` marker did the reverse and produced exactly that bug — every `toolkit` tool shipped with no `required` array at all, so `Bash` declared `command` optional.
- **`jsonschema` struct tags carry the rest of the subset**, and only the subset: `description`, `title`, `enum`, `const`, `format`, `pattern`, `minLength`, `maxLength`, `minItems`, `default`. `required` is **not** a member — it is derived. An unrecognized or out-of-subset tag key panics at `NewTool` naming the key, never silently ignored, because a dropped tag is the same class of defect as a dropped keyword.
- **Nested structs are inlined, not hoisted.** The reflector emits the nested shape in place. No `$defs`, no `$ref`: Gemini rejects both outright and every renderer would have to undo the hoisting anyway. Recursive types have no inline form and are rejected at the gate (D34).
- **Edge Go types map by prevailing schema-library convention, bounded by the subset.** Where the conventional output is in-subset the reflector emits it: `time.Time` → `{"type": "string", "format": "date-time"}`; an embedded struct's fields are flattened into the parent's properties exactly as `encoding/json` promotes them; a `json:"-"` field is omitted.
- **`NewTool` panics on an `In` the reflector cannot map into the subset — fail early, fail loudly.** A type with no honest in-subset schema (`any`, `json.RawMessage`, `chan`/`func`/`complex`, a Go map, a recursive struct) and an unrecognized or out-of-subset `jsonschema` tag key are programming errors visible in source at construction time, so they surface as a panic naming the offending field and construct — the `regexp.MustCompile` convention — never a silent guess and never a defect deferred to first use. The `Send` gate (D34) still validates every tool identically; its irreplaceable job is the schemas that never pass through `NewTool` (MCP servers), and it backstops everything else.
- **AgentKit owns the reflector; `invopop/jsonschema` is dropped.** The library's value was type mapping, but its output requires undoing on every axis that matters here — it stamps `additionalProperties: false` unconditionally (now adapter-owned), hoists nested structs into `$defs` (now inlined), emits a `$schema` URL (now excluded), renders `map[int]T` as `patternProperties` and `any` as the boolean schema `true` (both out of subset), and emits a dangling `$ref` with no `$defs` block for recursive types under the configuration required here. Normalizing that output is strictly more code than reflecting into a small target directly, and leaves the canonical form defined by a dependency's defaults rather than by us.
- **`Call` returns `(string, error)`** — text-only result. A returned `error` becomes a `ToolResultBlock{IsError: true}` fed back to the model (in-band signal the model can recover from), not a turn-ending transport failure.
- **Tool names are unique within the set; duplicates are rejected at the `Send` boundary.** `Tools` is a bare exported slice the consumer appends to (D1), so AgentKit first observes the assembled set at `Send`; that is the only chokepoint where uniqueness can be enforced.
- **MCP tools reuse this exact abstraction** (D17): each is wrapped as an ordinary `Tool` whose `JSONSchema()` is the server's `inputSchema`. That schema is not produced by our reflector, so it is the one source that can leave the subset; it is gated identically at `Send` (D34) and rendered identically per provider (D22).

**Rejected.**
- *`RawTool`, a hand-written-schema escape hatch* — carried for the whole life of the library with **zero** production callers, and it was the sole reason `Send` needed a schema well-formedness check. A second way to build a tool that nobody used is complexity paid for a hypothetical future. Tests that need a hand-written schema use a test-only helper, not a public API.
- *A generic `Tool[In]` interface* — can't live in one `[]Tool`; forces `[]any`/reflection in the loop. Erase at construction.
- *`Call` returning `(any, error)`* — text-only scope makes the result always text; `string` is honest and avoids a marshal step the consumer can't inspect.
- *Consumer hand-writes JSON Schema as the primary path* — tedious and error-prone, and it drifts silently when the struct changes. Deriving from the type is what makes drift impossible.
- *Keeping `invopop/jsonschema` and normalizing its output* — writes the same amount of code while leaving the canonical schema shaped by a third party's defaults; a dependency upgrade could then change what reaches a provider.
- *Deferring reflector-detectable violations to the `Send` gate* — a defective input struct is visible at construction; letting it flow to the first `Send` reports the error later, further from the defect, for no gain. Fail early.
- *`NewTool` returning `(Tool, error)`* — every correct call site would pay an error-handling tax for a mistake that is static in the source and cannot occur at runtime; a panic is the honest signal for programmer misuse.
- *Method-based registration (`conv.AddTool`)* — unnecessary; `Tools` is an exported field and append is idiomatic.

**Verification.**
- R-WYZP-N2VB — a `Tool` from `NewTool` produces a `JSONSchema()` that reflects the struct's fields, with each property's `description` taken from its `jsonschema` tag, and is byte-stable across calls (derived once, cached) and immune to mutation of a previously returned slice.
- R-XZ8K-R3NX — the reflector marks a field **required** exactly when its `json` tag lacks `,omitempty` and its type is not a pointer: for a struct with one plain and one `,omitempty` field, `required` contains the plain field's name and not the other; a build deriving required-ness from a `jsonschema:"required"` marker fails this.
- R-Y0GH-4VEM — a `jsonschema` tag key inside the subset (`enum`, `format`, `pattern`, `minLength`, `maxLength`, `minItems`, `const`, `title`, `default`) appears verbatim in the derived schema, and a tag key outside it (e.g. `minimum`) panics at `NewTool` with a message naming that key — never dropped silently; a build that defers the bad key to the `Send` gate or emits it fails this.
- R-Y1OD-IN5B — the derived schema for a struct with a nested struct field contains the nested shape **inline**, and contains no `$schema`, `$defs`, `$ref`, or `additionalProperties` key at any depth.
- R-DIVW-07P0 — edge Go types with a faithful in-subset schema reflect by convention: a `time.Time` field yields `{"type": "string", "format": "date-time"}`, an embedded struct's fields appear flattened in the parent's `properties`, and a `json:"-"` field is absent; a reflector that emits `time.Time` as an object fails this.
- R-AIWI-P5JP — `NewTool` panics, with a message naming the offending field and construct, on an input struct containing an `any` or `json.RawMessage` field, a Go map field, or a recursive (direct or mutual) struct reference; a build that constructs the `Tool` and defers the failure to the `Send` gate, or guesses an object shape, fails this.
- R-Y2W9-WEW0 — `RawTool` is absent from the public API, and `NewTool` is the only exported constructor producing a `Tool`; the `agentkit` package exports no symbol accepting a hand-written schema.
- R-X07M-0UM0 — when the model emits a tool call, the auto-loop decodes the input into the tool's `In` type and invokes `fn` with the decoded value; the string return becomes the `ToolResultBlock.Content`.
- R-X1FI-EMCP — a `fn` returning an error yields a `ToolResultBlock{IsError: true}` fed back to the model and the turn continues (not a terminal stream error).
- R-SZH4-PB1G — a `Send` whose `Tools` contains two tools sharing a `Name()` surfaces `ErrInvalidConfig` (matchable via `errors.Is`) through the returned `Stream`, leaves `History` unchanged, and issues no provider call.
