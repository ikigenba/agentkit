# Decision 41 — xAI SuperGrok subscription store

**Decision.** The refresh machinery for SuperGrok / X Premium OAuth lives in an **opt-in subpackage `xai/subscription`** so consumers that never use it never import disk or OAuth code; the `TokenSource` seam it feeds is declared in `xai` proper (D40). **The package contains no login flow**: obtaining the initial credential is the consumer's job, done outside AgentKit with a generic OAuth login tool whose stdout — the token endpoint's response, verbatim — is saved as the credential file (research §20.1–§20.2).

```go
// package xai/subscription — opt-in: disk + OAuth-refresh machinery, never
// imported by the core provider path. No login flow lives here.

const (
    clientID    = "b1a00492-073a-47ea-816f-4c329264a828"
    tokenURL    = "https://auth.x.ai/oauth2/token"
    refreshSkew = 5 * time.Minute
)

// Load opens the credential file at exactly the path the consumer names — no
// path discovery, no env reading (product: no ambient credential sourcing).
// The file is the raw RFC 6749 token-endpoint response, verbatim (research
// §20.1): top-level access_token, refresh_token, id_token; other standard
// fields (token_type, expires_in, scope) ignored. A file missing
// access_token fails loudly with an error naming what is missing; no partial
// store is returned. No account-id claim is required or extracted.
func Load(path string) (*Store, error)

// Store implements xai.TokenSource over the credential file: it returns the
// current access token, refreshing proactively when the JWT exp is within
// refreshSkew (and not reactively on 401 — a 401 maps to ErrAuthentication
// and the turn fails). Refresh POSTs application/x-www-form-urlencoded to
// tokenURL with grant_type=refresh_token, refresh_token, client_id (public
// client, no secret). The rotated tokens are written back atomically at mode
// 0600 in the same raw token-response shape, carrying forward the prior
// refresh_token and id_token when the refresh response omits them. Single-
// flight so concurrent requests do not race the file. Token values are never
// logged.
func (s *Store) Token(ctx context.Context) (bearer string, err error)
```

Settled choices:
- **The credential file is the token response, verbatim.** One supported shape. The grok CLI wrapper (`~/.grok/auth.json`, keyed by `issuer::client_id`) is not read (research §20.1).
- **No account id.** The public API accepts the bearer alone (research §20.3). Load does not fail a file whose JWTs lack `team_id` / `principal_id`.
- **Client id and token URL are baked in.** They are the public Grok Build OIDC client and the discovered token endpoint (research §20.2). Not consumer configuration.
- **Refresh keeps the file self-sufficient.** Same carry-forward rule as D25, for the same reason: refresh responses may omit `refresh_token` / `id_token`.
- **No login in the library, and no terminal IO.** Login is a separate program's whole job. Nothing in the package touches network endpoints other than the token-refresh endpoint.
- **Mechanism in agentkit, policy in the consumer.** `subscription.Load(path)` takes an explicit path. `~/.agentrepl/xai-auth.json` is a consumer convention, never a default AgentKit discovers.
- **Independent lineages.** Refresh rotates a shared refresh-token lineage. The live test is read/use only against a file whose lineage may be shared; refresh-and-rewrite is exercised only against fakes or an expendable file.
- **No reactive refresh-on-401.** Matches the OpenAI subscription discipline (research §15.3): a 401 is `ErrAuthentication` and the turn fails loudly.

**Rejected.**
- *Reading the grok CLI wrapper format* — a second shape doubles every load/rewrite test for a file AgentKit is not the writer of.
- *Requiring `team_id` / `principal_id` at Load* — unused on the wire.
- *Sharing `openai/subscription` as a generic OAuth store* — the two vendors differ in token URL, client id, required claims, and TokenSource arity. A generic store would encode the union of both accidents.
- *An in-library login flow* — rejected for OpenAI in D25; same here.
- *Reactive refresh on 401* — silent retry with a new token hides an expired session; the turn fails and the consumer re-auths.

**Verification.**
- R-DTW8-9X67 — `Load` on a file holding a raw token-endpoint response (top-level `access_token` / `refresh_token` / `id_token`, no wrapper object) succeeds, and `Token` returns that `access_token` as the bearer when the JWT is unexpired.
- R-DV44-NOWW — `Load` fails loudly, returning no store, on a file with no top-level `access_token` (including a grok-CLI-wrapper-shaped file whose token sits nested under an issuer key), with an error naming `access_token`.
- R-DWC1-1GNL — a `Store` whose access token is expired (or within the 5-minute skew) refreshes at the token endpoint (fake OAuth server) with `grant_type=refresh_token` and the baked client id, retries carry the new bearer, the rotated tokens are written back atomically with mode `0600`, and N concurrent `Token` calls produce exactly one refresh request (single-flight, asserted on the fake server's request count).
- R-DXJX-F8EA — after a refresh whose response omits `refresh_token` and `id_token`, the rewritten file is still the raw token-response shape and carries the prior `refresh_token` and `id_token` forward, and a fresh `Load` of that rewritten file succeeds; after a refresh whose response *does* rotate them, the rewritten file carries the new values.
- R-DYRT-T04Z — **live** (gated on `XAI_SUBSCRIPTION_AUTH_FILE` naming a raw token-response file; skips cleanly when the env is unset or the file is absent): `subscription.Load` + `xai.New(xai.Subscription(store))` completes one short real `Send` returning an assembled non-error message — read/use only, no refresh forced against a shared-lineage file — proving the public `api.x.ai` bearer contract against the real service.
