# Decision 34 — The canonical tool-schema subset, owned by root

**Decision.** AgentKit defines **one canonical subset of JSON Schema that every tool's input schema must fit**, owned by the root `agentkit` package, enforced identically for every tool from every source, and independent of which provider a conversation is configured with. A schema outside the subset is `ErrInvalidConfig` at the `Send` boundary. Nothing is dropped, nothing is warned about, and no schema construct ever reaches a provider that cannot express it.

The subset is **derived, not chosen**: it is exactly the set of constructs with a faithful rendering in *every* provider dialect AgentKit supports (research §18). Membership is a fact about the measured dialects, not a taste judgment, and it widens automatically when a provider's dialect does.

Root owns it because root is the only package that can. A `Conversation` holds exactly one `Provider`, and provider packages import root (never the reverse), so root cannot reach a dialect description belonging to a provider that is not configured. Enforcing "renderable by all providers" is therefore only possible from root. This is a deliberate reversal of the superseded model in which root held no schema knowledge and each provider declared its own narrowness through an optional capability interface; that model can only ever enforce against the configured provider, which would let a tool pass on Anthropic and fail on Gemini.

```go
package agentkit

// Constructs permitted in a tool input schema. Derived from research §18: a
// construct is a member iff every supported provider dialect can render it
// faithfully. Root owns this because root cannot import provider packages and a
// Conversation holds only one Provider, so no per-provider description can
// answer "renderable everywhere".
//
// validateToolSchema reports the first violation as a human-readable reason
// naming the offending JSON Pointer and construct. It is the sole authority on
// membership; adapters render, they never re-decide.
func validateToolSchema(schema json.RawMessage) error
```

**The subset.** Permitted: `type` (single value), `description`, `title`, `properties`, `required`, `items`, `enum`, `const`, `anyOf`, `oneOf` (rendered as `anyOf`), `$ref`/`$defs` (inlined at render time), `minLength`, `maxLength`, `pattern` (RE2-safe: no lookahead/lookbehind), `minItems` (values 0 or 1 only), `format` (excluding `uri`), `default`, and a two-branch nullable union.

Excluded, each because at least one dialect cannot express it: `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `maxItems`, `uniqueItems` (Anthropic strict rejects); `allOf`, `not`, `if`/`then`/`else` (OpenAI strict rejects `allOf`, all three reject `not`); `patternProperties` (Anthropic strict rejects); recursive `$ref` (Anthropic and Gemini reject); `additionalProperties` in any authored form; `format: "uri"` (OpenAI strict rejects while Anthropic accepts — an irreconcilable conflict, so it leaves the subset); `propertyNames`, `prefixItems`, `contains`, `dependentSchemas`, `unevaluated*`, `$schema`, `$id`, `$comment`.

Settled choices:
- **`additionalProperties` is adapter-owned and never authored.** It is mandatory on every object for Anthropic and OpenAI under strict mode and a hard 400 on Gemini (research §18.1, §18.2, §18.3), so no authored value could be correct for all three. A tool schema containing it is rejected; each adapter injects or omits it per its own dialect (D22). "Closed object" is the invariant meaning — Anthropic and OpenAI spell it with the keyword, Gemini by omission, since Gemini only ever generates declared properties.
- **Rejection is whole-toolset, not per-tool.** One offending tool fails the entire `Send` with `ErrInvalidConfig`, `History` unchanged and no provider call — matching the existing duplicate-name and malformed-schema gates rather than inventing a second, softer failure mode for the same class of problem.
- **The gate replaces the parseability check.** The superseded `validJSONSchema` accepted anything that unmarshalled to a `bool` or an object, so `{"type":"nonsense"}` and an unresolvable `$ref` both passed. Subset validation subsumes and strictly strengthens it.
- **Error text names the construct and its location**, so a rejected tool is diagnosable without re-reading this document.
- **Go types that cannot be expressed are rejected at the gate, not at construction.** A `map[...]...` field reflects to a schema-valued `additionalProperties` and a recursive type to a recursive `$ref`; both are out of the subset. `NewTool` cannot report an error (it returns a bare `Tool`), so the gate is the only honest place to surface it.

**Rejected.**
- *Warning on an unrenderable construct instead of erroring* — the superseded model. Research §18.4 removes its premise: a non-strict provider that accepts a keyword does not honor it, so "warn and proceed" ships a silently weakened contract and the observed failure is wrong tool arguments at runtime, not graceful degradation. A warning emitted on every turn is indistinguishable from silence.
- *Per-provider subsets, enforced only against the configured provider* — strictly more expressive, and still loud, but a tool would pass on one provider and fail on another. Uniformity across providers is the product promise; expressiveness is not.
- *Providers declaring their own dialects through a capability interface* — structurally impossible to use for uniform enforcement, since root cannot import provider packages and holds only the configured one.
- *Dropping unrenderable constructs mechanically per provider* — indistinguishable from the silent weakening this Decision exists to remove.
- *Gemini's `parametersJsonSchema` field to widen the subset* — it accepts full JSON Schema, including invented keys, by dropping unsupported keywords silently (research §18.1). It trades our visible failure for the provider's invisible one.

**Verification.**
- R-XLTO-JMIA — a `Send` whose tool set contains a schema using a construct outside the subset (e.g. `minimum`, `not`, `allOf`, `patternProperties`, or an authored `additionalProperties`) surfaces `ErrInvalidConfig` (matchable via `errors.Is`) through the returned `Stream`, leaves `History` unchanged, and issues **no** provider call; the error text names the offending construct and its location in the schema. A schema using only subset constructs passes the gate.
- R-XRX6-GH7R — the identical out-of-subset schema is rejected with `ErrInvalidConfig` under **every** provider, including one whose own dialect would accept the construct (e.g. `minimum` under OpenAI, `allOf` under Anthropic), proving enforcement is provider-independent; a build that consults the configured provider's dialect and admits the construct fails this.
- R-XN1K-XE8Z — a tool whose input struct contains a Go map field reflects to a schema-valued `additionalProperties` and is rejected at the `Send` gate with `ErrInvalidConfig` naming that construct, rather than being sent with the map's value schema silently lost.
- R-XO9H-B5ZO — a tool whose input struct is recursive (directly or mutually) is rejected at the `Send` gate with `ErrInvalidConfig` naming the recursive reference; no provider call is issued and no dangling `$ref` is emitted.
- R-XQPA-2PH2 — an MCP tool whose server-supplied `inputSchema` leaves the subset is rejected at the `Send` boundary with `ErrInvalidConfig` whose text attributes the failure as `<server>.<tool>`, and the whole `Send` fails rather than the single tool being dropped or degraded.
