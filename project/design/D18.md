# Decision 18 — The embeddings consumer surface: the `Embedder` object and the `Embed` verb

**Decision.** Embeddings get their **own** consumer object — an `Embedder` — and **one** verb — `Embed` — that returns `(*EmbedResult, error)` in plain idiomatic Go. The `Embedder` is the embeddings analogue of `Conversation` (D1): a bundle of configuration the consumer mutates between calls, threaded explicitly into each call. It is deliberately *not* a `Conversation` and shares none of the conversational machinery. The embeddings surface follows the same free-flow, dumb-layer rules as chat (D5): the model is an ungated string the provider judges, the price row is a consumer-supplied sibling of the model field, and cost resolves exactly as in chat (D16) — supplied rates, else zero + `WarnCostUnknown`.

```go
package agentkit

// Embedder is a configured embeddings client: provider, model, and the options
// that shape every Embed call, plus the cumulative usage/cost it accrues over
// its lifetime. Like Conversation it is a plain struct literal the consumer
// mutates between calls (switching provider/model/dimension is field
// assignment), and like Conversation it is owned by one goroutine and is not
// safe for concurrent use (no internal locking).
type Embedder struct {
    Provider   EmbeddingProvider  // swappable between calls; carries its own credentials (D19)
    Model      string             // swappable between calls; free-flow — the provider judges it (D5 rules)
    Pricing    *EmbeddingPricing  // sibling of Model: consumer-supplied rates (typically one catalog lookup, D26); nil → zero + WarnCostUnknown (D16/D20)
    Dimensions int                // 0 → the model's native dimension; non-zero → requested target, verified on return (below)
    Retry      RetryPolicy        // reused verbatim from D11; zero value = defaults

    // cumulative accounting (unexported); read via TotalUsage()/TotalCost()
}

// InputType is the per-call query-vs-document role. It is an Embed argument, not
// an Embedder field, because the same Embedder legitimately embeds both queries
// and documents (D19/research §12.3 — it cannot be config). The zero value is
// InputUnspecified, so a caller that does not care passes it (or InputUnspecified)
// and every provider behaves correctly: Google maps it to a task_type, OpenAI
// ignores it (D19).
type InputType int
const (
    InputUnspecified InputType = iota // default; no role hint
    InputQuery                        // a search query (Google: RETRIEVAL_QUERY)
    InputDocument                     // a stored document (Google: RETRIEVAL_DOCUMENT)
)

// Embed turns inputs into one unit-normalized vector per input, in input order.
// inputs is a batch of any size (a single text is a batch of one); AgentKit
// chunks it across the provider's per-call limit internally (D19). role tags the
// whole batch. Boundary validation covers only what AgentKit itself owns — a
// usable Embedder (provider + model present) and non-empty input; model
// validity, dimension acceptance, and input length are the provider's judgment.
//
// On success err is nil and *EmbedResult is non-nil. On failure *EmbedResult is
// nil and err carries the uniform D7 error (errors.Is for the category, errors.As
// for a provider *Error).
func (e *Embedder) Embed(ctx context.Context, inputs []string, role InputType) (*EmbedResult, error)

// EmbedResult is one Embed call's result. Vectors[i] is the unit-normalized
// embedding of inputs[i], same order, same length as inputs. Warnings are
// non-fatal advisories (never a reason err is non-nil) — including
// WarnCostUnknown when no pricing was supplied. Usage/Cost are this call's
// figures (summed across internal chunks, D19/D20).
type EmbedResult struct {
    Vectors  [][]float32
    Warnings []Warning      // reused from chat; non-fatal
    usage    EmbeddingUsage // D20
    cost     Cost           // D20 (shared root Cost type)
}

func (r *EmbedResult) Usage() EmbeddingUsage // this call's input-token usage (D20)
func (r *EmbedResult) Cost() Cost            // this call's resolved cost (D20; 0 + warning when unpriced)

// Cumulative accounting over the Embedder's life, mirroring Conversation's
// TotalUsage()/TotalCost() (D15/D16) — the sum of every successful Embed call.
func (e *Embedder) TotalUsage() EmbeddingUsage
func (e *Embedder) TotalCost() Cost
```

Construction and a provider/model/dimension switch are plain field work, exactly like `Conversation`:

```go
emb := &agentkit.Embedder{
    Provider: openai.NewEmbedder(openai.APIKey(key)),
    Model:    "text-embedding-3-small",
    Pricing:  catalog.EmbeddingRates("text-embedding-3-small"), // advisory lookup; or a hand-written row; or nil
}
res, err := emb.Embed(ctx, []string{"hello", "world"}, agentkit.InputDocument)
// switch provider/model between calls — only configuration changes:
emb.Provider = google.NewEmbedder(google.APIKey(gk)); emb.Model = "gemini-embedding-001"; emb.Dimensions = 1536
qres, err := emb.Embed(ctx, []string{"a search query"}, agentkit.InputQuery)
```

Settled choices:
- **A separate `Embedder` object, not an overloaded `Conversation`.** Embeddings have no system prompt, tools, history, reasoning, streaming, or tool loop; the two objects share *foundations* (`RetryPolicy`, the D7 errors, the root `Cost`/`Warning` types, the D16 cost-resolution philosophy) by value, not the chat surface.
- **`Embed(...) (*EmbedResult, error)` — idiomatic Go, not a `*Stream`.** An embeddings call has nothing to stream; the bare return is the honest shape, with the D7 error model unchanged.
- **Free-flow model, no registry gate.** The former "unknown model id ⇒ `ErrInvalidConfig` before the call" is gone with the registries (D5): the model string flows to the wire and the provider judges it. Boundary validation keeps only AgentKit-owned checks: a missing `Provider`/`Model` is `ErrInvalidConfig`; empty input is `ErrInvalidInput`.
- **The requested dimension is verified on return, not gated up front.** With no per-model spec to consult, the pre-flight producible-range check is replaced by a **post-return check the promise actually needs**: if `Dimensions != 0` and any returned vector's length differs, `Embed` fails loud (`ErrInvalidConfig`) rather than returning mis-sized vectors — catching both a provider that rejected the parameter *and* one that silently ignored it. Model-knowledge-free, and strictly stronger than trusting a spec table.
- **Cost resolves per D16, embeddings flavor.** `Embedder.Pricing` supplied → `EmbeddingPricing.Cost(usage)` (D20). Nil → the call succeeds with `Cost() == 0` and a `Warning{Setting:"cost", Code:WarnCostUnknown}` in `EmbedResult.Warnings` — every affected call, same honesty rules as chat. (Embedding providers report no cost on their responses, so there is no reported-cost arm today; if one appears, the chat precedence applies verbatim.)
- **`Dimensions` is an `Embedder` field (per-model config); `InputType` is an `Embed` argument (per-call).** Unchanged reasoning: one `Embedder` embeds both queries and documents, so role rides the call; the target dimension is config.
- **Batch in, ordered vectors out; a single text is a batch of one.** Unchanged.
- **Per-call and cumulative accounting, mirroring chat.** Unchanged surfaces over the new resolution.
- **No embeddings event log in v1.** Unchanged; deferred, not rejected.

**Rejected.**
- *Registry-gated model validity and pre-flight dimension range checks* — the previous design; requires per-model spec tables in the provider layer (model knowledge, evicted by D5) and gates day-one embedding models. The post-return length check keeps the never-silently-wrong-size promise without any table.
- *Erroring when `Pricing` is nil* — re-gates running on price data; zero-plus-warning per D16.
- *Overloading `Conversation`/`Send` for embeddings* — unchanged rejection.
- *Mirroring `*Stream` with a fake single event* — unchanged rejection.
- *`InputType` as an `Embedder` field* — unchanged rejection (the two-client trap).
- *A separate single-string `EmbedOne` verb* — unchanged rejection.

**Verification.**
- R-Y5RV-WB3T — an `Embed` call returns exactly one vector per input in input order, and the identical calling code produces a working result against both OpenAI and Google (config-only swap holds at the surface; the only change between the two runs is `Provider`/`Model`).
- R-Y6ZS-A2UI — changing `Provider`/`Model` (and `Dimensions`) between two `Embed` calls runs the second call against the newly selected provider/model with no other change to the calling code.
- R-D5AV-SNAL — `Embed` on an `Embedder` missing a required config field (provider or model) returns `ErrInvalidConfig` (matchable via `errors.Is`) and issues no provider call; a *present but uncataloged* model string is **not** rejected locally — it reaches the wire and any rejection is the provider's typed error.
- R-Y9FL-1MBW — `Embed` with empty input — a nil/empty `inputs` slice, or a batch containing an empty string — returns `ErrInvalidInput` (matchable via `errors.Is`) and issues no provider call.
- R-YANH-FE2L — `role` is an `Embed` argument defaulting to `InputUnspecified` (the zero value); the same call succeeds on both OpenAI and Google for each of `InputUnspecified`/`InputQuery`/`InputDocument` (the provider-side effect of the role is D19's concern).
- R-YBVD-T5TA — with `Dimensions == 0`, returned vectors have the model's native dimension; with `Dimensions` set to a value the selected model can produce, every returned vector has exactly that length.
- R-D6IS-6F1A — with `Dimensions != 0` and a provider response whose vectors have a *different* length (a provider that ignored the parameter, simulated on a fake server), `Embed` fails loud with `ErrInvalidConfig` naming requested-vs-returned sizes and returns no vectors — never mis-sized vectors.
- R-D2V3-13T7 — with `Embedder.Pricing` supplied, `EmbedResult.Cost()` equals `EmbeddingPricing.Cost(usage)` for the call's usage and `Embedder.TotalCost()` accumulates it across calls.
- R-D42Z-EVJW — with `Embedder.Pricing == nil`, the call still succeeds with `Cost() == 0` and exactly one `Warning{Setting:"cost", Code:WarnCostUnknown}` in `EmbedResult.Warnings` — on every affected call — and the warning disappears once `Pricing` is supplied.
