# Decision 31 — The `ocr` package: the document-text tool, its cache, and its preview

**Decision.** A new leaf subpackage `github.com/ikigenba/agentkit/ocr` (package `ocr`) provides one `agentkit.Tool` that turns a scanned PDF or raster image into text. It is deliberately **not** part of `toolkit`: every `toolkit` tool is free, offline, instant, and deterministic, and this one costs money per page, needs a credential, takes seconds, and reaches the network. Folding it in would make `toolkit`'s confinement promise misleading — a file tool that rejects `../secrets` while uploading a file *inside* the root to a third party is a guarantee that no longer means what its documentation says.

```go
// package ocr

// OpenRouter is the document-parsing backend. The consumer constructs it and
// passes it in; Tool never builds one, never reads an environment variable, and
// never touches a credential store (Conventions: explicit credentials).
type OpenRouter struct {
	APIKey  string       // required
	Model   string       // "" = defaultModel; a billing knob only (D32)
	BaseURL string       // "" = https://openrouter.ai/api/v1
	HTTP    *http.Client // nil = internal/httpx default; tests point this at httptest
}

// Tool returns the OCR tool, declared to the model as "OCR".
//
//	root     — source paths resolve here and may not escape it (D27 confinement)
//	cacheDir — where extraction artifacts are written; required, never ""
func Tool(root, cacheDir string, backend *OpenRouter) agentkit.Tool

type ocrInput struct {
	FilePath string `json:"file_path"` // required; the only field
}

const maxPreviewCharacters = 30_000
```

Settled choices:

- **The model chooses a document, never a destination.** The input schema carries `file_path` and nothing else. The wiring service names `cacheDir` once at construction, because where files land is a deployment fact it owns and the model has no legitimate opinion about. This is not tidiness: a cache is only a cache if the same input maps to the same output path, and a model-chosen destination re-OCRs the same document at three paths across three turns. It also removes a second confinable path from the model's reach.
- **`cacheDir` is required.** An empty value meaning "don't cache, return inline" would create a second result shape and a second failure mode. One contract.
- **The cache entry is a directory**, named `<source-stem>-<hash8>` where `hash8` is the first 8 hex chars of the SHA-256 of the **source file's bytes**. Content-addressed, so an edited source misses correctly; stem-prefixed, so a human or a debugging session can scan the directory and see what is in it. The same bytes under two different filenames are extracted twice — a rare case, traded knowingly for legibility.
- **Two artifacts, one authoritative.** `response.json` is the provider's response body byte-for-byte and is the cache and the source of truth; `transcript.md` is a deterministic materialized view derived from it by `Transcript` (D32). Storing the raw response is what makes a parse fix cheap forever: correct the deriver, walk the cache, rewrite every transcript, spend nothing. Storing only the derived text would mean re-paying the per-page fee for the whole corpus to fix a formatting bug.
- **`transcript.md`, not `.txt`.** The engine returns Markdown — `##` headings and pipe tables (D32) — so the extension states what the file is.
- **The transcript is regenerable, and repairs itself.** On a cache hit the tool reads `transcript.md`; if it is missing it is re-derived from `response.json` and written, with no network call. `find <cacheDir> -name transcript.md -delete` therefore rebuilds the whole corpus on next access at zero cost, so no migration tooling or version stamping is needed.
- **The tool returns a preview plus the transcript path**, always in that one shape, never branching on size. Always-write means the contract has one form and the common small document still completes in a single call because its preview contains the whole text. The preview is a **verbatim prefix** of `transcript.md` — never reworded, never summarized — capped at **30,000 characters** (matching D27's cap, so an agent learns one ceiling, a deliberate duplication of a value rather than shared code across packages) and cut at the **last page boundary that fits**. Characters set the ceiling because only a character count bounds context; page boundaries choose the cut so a Markdown table is never severed mid-row. A single page larger than the cap falls back to the last line boundary, so one oversized page still cannot breach the bound. Both outcomes are marked explicitly — the complete case says so, the truncated case names shown pages, shown characters, and totals — so nothing is ever silently cut.
- **`response.json` is never named to the model.** It is an operator and debugging artifact: one enormous line containing base64 image payloads, on which `Read` is a context bomb and `Grep` returns 25,000-character lines. Reaching it would need `Bash`, the one deliberately unconfined tool (D27). The model's path to anything past the preview is `Read`/`Grep` on `transcript.md`.
- **Nothing is written or cached on failure.** A failed extraction (D32's error cases) leaves the cache untouched, so a transient failure is never frozen into a permanent empty result that every later call happily serves.
- **No pre-flight size guard.** Measured behavior forbids one: a 23.3MB / 114-page PDF succeeded while a 24.1MB / 385-page PDF was rejected, because the provider's 30MB ceiling applies to the *images extracted from inside* the document, not the file (research §17.4). A guard on `stat` size would reject working files and admit failing ones. The tool sends the document and handles the failure well.
- **Source paths are confined to `root`** by the same rule as D27's file tools, symlink-resolution included; writes are confined to `cacheDir`. Confinement is checked before any network call, so a rejected path never costs money.
- **The backend is a caller-supplied value, not an interface — yet.** Auth-mode routing is a per-capability judgment (product Scope), so a second backend on subscription auth is a named future, not speculation. But the two candidate shapes differ materially — OpenRouter returns Markdown only, while a direct Mistral OCR API also returns bounding boxes, typed blocks, and confidence scores (research §17.6) — so an interface minted against the single implementation in hand would encode its limitations. The *parameter position* is reserved instead: introducing `ocr.Extractor` later and widening the parameter to it is source-compatible, since `*OpenRouter` already satisfies it and every call site compiles unchanged. The irreversible mistake is not the missing interface; it is `Tool` constructing its own backend or reading a key, which is prohibited above.

**Rejected.**
- *Put the tool in `toolkit`* — destroys the one property that makes `toolkit` describable (free, offline, instant, deterministic, confined) and turns its confinement guarantee into a false statement, since the path is confined but the contents are uploaded.
- *An SPI in the root package with the tool in `toolkit` and the backend in `openrouter`* — smears one capability across three packages, puts a document-extraction concept into the provider-agnostic core where it is not universal, and creates a sub-package→sub-package edge that would drag the OpenRouter client into every `toolkit` consumer, against D9's dependency isolation.
- *Return the text inline with no file* — caps the model's reach at 30,000 characters; a 114-page document produced ~920,000 characters of text, roughly 30× the cap.
- *Return only the `response.json` path* — the model then needs `jq` through the unconfined `Bash`, and the wire-format knowledge that D32 isolates in one tested function would move into the model's head, where nothing covers it.
- *Page bounds (`offset`/`limit`) on the OCR tool* — duplicates paging `Read` already does and searching `Grep` already does, and adds a second cap. Conversion is this tool's job; presentation is `Read`'s.
- *Model-supplied output path* — breaks cache determinism and adds a confinable path for no gain.
- *Eviction, TTL, or a size limit on the cache* — a policy engine before any consumer has asked for one; the service owns the directory and can delete it. D27 already rejected this shape of speculative configuration once.
- *Writing the extracted images as separate files* — they are capped at 8 per document regardless of length (research §17.3), so writing them would imply a completeness the data does not have. They remain preserved verbatim inside `response.json`.

**Verification.**
- R-V1UC-V54E — `Tool` returns a tool whose declared name is `OCR` and whose input schema has exactly one property, `file_path`, and no destination/output-path field.
- R-V329-8WV3 — a `file_path` resolving outside `root` (via `../` or via a symlink inside the root) is rejected with an error, and **no HTTP request is issued** (asserted against an `httptest` backend that records request count = 0).
- R-V4A5-MOLS — a successful extraction writes exactly `<cacheDir>/<stem>-<hash8>/response.json` and `<cacheDir>/<stem>-<hash8>/transcript.md`, where `hash8` is the first 8 hex characters of the SHA-256 of the source bytes.
- R-V6PY-E836 — editing the source file's bytes (same filename) produces a **different** cache directory and issues a new HTTP request; the previous directory is left intact.
- R-V7XU-RZTV — a second call on an unchanged source issues **no** HTTP request (recorded request count stays 1) and returns the same transcript path.
- R-V95R-5RKK — with `transcript.md` deleted but `response.json` present, the next call regenerates `transcript.md` byte-identically and issues **no** HTTP request.
- R-VADN-JJB9 — a transcript at or under 30,000 characters is returned in full, with a marker stating the transcript is complete.
- R-VBLJ-XB1Y — a transcript exceeding 30,000 characters is returned cut at the **last page boundary that fits**: the returned preview is a verbatim prefix of `transcript.md`, is ≤ 30,000 characters, ends at a page boundary, and carries a marker naming shown pages, shown characters, and total characters.
- R-VCTG-B2SN — when page 1 alone exceeds 30,000 characters the preview falls back to the last line boundary and is still ≤ 30,000 characters (a single oversized page cannot breach the bound).
- R-VE1C-OUJC — a failed extraction (D32 error cases) writes nothing: the cache directory does not exist afterwards, and a subsequent successful call performs a fresh HTTP request.
- R-VF99-2MA1 — the tool result names the `transcript.md` path and never mentions `response.json`.
