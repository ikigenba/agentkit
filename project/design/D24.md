# Decision 24 — The `openrouter` provider

**Decision.** `openrouter` is a first-class chat provider package over the shared `internal/openaicompat` Chat-Completions adapter (D5/D12), reaching hundreds of models — vendor-namespaced free-form slugs like `anthropic/claude-opus-4-8`, `z-ai/glm-5.2` — through one wire at `https://openrouter.ai/api/v1` (research §14). It is the design's proof case for the dumb-layer rules: free-flow model strings (day-one models, `:nitro`/`:floor` suffixes for free), **provider-reported cost** (the only adapter that populates `RoundTrip.ReportedCost`, D9/D16), routing steered through the opaque `ProviderOptions` pass-through (D9), and BYOK-vs-credits requiring **nothing in code** (account configuration; the reported cost is correct on both paths).

```go
// package openrouter

type Credential interface{ isCredential() } // closed: one member today
type APIKey string                          // implements Credential; dashboard-created or PKCE-minted (research §14.5) — same static key either way

func New(cred Credential, opts ...Option) *Provider // Chat-Completions wire, base https://openrouter.ai/api/v1 baked in
```

Settled choices:
- **Thin vendor package over `internal/openaicompat`**, exactly like `zai` (D5): baked-in base URL, bearer auth, own `Error.Provider` label (`"openrouter"`), no public adapter. What it adds beyond zai's construction is confined to three seams the shared adapter exposes as configuration: cost extraction, reasoning encoding, and (shared by all compat providers) the `ProviderOptions` merge.
- **Reported cost from the response — the ground-truth arm of D16.** Every OpenRouter response carries `usage.cost` (credits, USD-pegged) plus `cost_details.upstream_inference_cost` automatically; streaming puts the usage object in the **final SSE frame**, exactly where `openaicompat` already reads token usage (research §14.2). The adapter computes `reported = cost + upstream_inference_cost` (the BYOK-correct total; `upstream_inference_cost` is 0/null on the credits path), converts credits→nano-USD once at this edge, and populates `RoundTrip.ReportedCost`. A response that omits the cost field entirely yields `ReportedCost() == (0, false)` and the D16 resolution falls through — never a fabricated figure.
- **Reasoning lowers to OpenRouter's normalized `reasoning` parameter** (research §14.4): `Level(s)` → `{"reasoning":{"effort":s}}`, `Budget(n)` → `{"reasoning":{"max_tokens":n}}`, `DisableReasoning()` → `{"reasoning":{"enabled":false}}`, unset → omitted. This is a different encoding than zai's `thinking`/`reasoning_effort` fields on the same wire, so it is per-provider configuration of the shared adapter, not a fork (D9 lowering table).
- **Routing rides `ProviderOptions`.** OpenRouter's `provider: {order, only, ignore, sort, max_price, quantizations, zdr, …}` object (research §14.3) is exactly the kind of fast-evolving vendor surface the opaque pass-through exists for; the typed convenience builder lives in the catalog layer (D26), never in core or in this package.
- **BYOK vs credits: zero client code.** Which path a call takes is OpenRouter account configuration; the key shape, the wire, and the cost math are identical. The design deliberately contains no BYOK awareness anywhere.
- **PKCE key-minting is out of scope.** OpenRouter's OAuth flow ends in an ordinary API key (research §14.5); where a key came from is the consumer's business. No OAuth machinery exists in this package (contrast D25, where the token itself is the living credential).

**Rejected.**
- *A generic `openaicompat`-named public provider* — vendor-named packages are the D5 pattern; OpenRouter is a specific service with specific cost/reasoning semantics, not a generic wire.
- *Typed routing options in core (`Request` fields)* — vendor-shaped types in the neutral core, growing with OpenRouter's release cadence; the opaque fragment + advisory builder keeps core closed.
- *Table-costing OpenRouter models* — a table across hundreds of daily-changing slugs is unmaintainable, and the response already states the truth; reported-cost-first is the D16 precedence.
- *Requesting cost via `usage: {include: true}`* — deprecated no-op; cost arrives unconditionally (research §14.2).
