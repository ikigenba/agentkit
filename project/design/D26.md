# Decision 26 — The advisory model catalog: `agentkit/catalog`

**Decision.** All model knowledge evicted from the provider layer (D5) lives in **one advisory data package, `agentkit/catalog`**: maintained reference data about known models — chat and embedding — plus lookup helpers and typed option builders. It is **consumer-facing only**: nothing in root `agentkit` or any provider package imports it, and nothing in the request path consults it. Its absence for a model restricts nothing (free-flow); its presence makes the common path effortless — one lookup resolves a model name to its provider, wire ids per route, rates, reasoning vocabulary, context size, and capability metadata.

```go
// package catalog

// Entry is everything the catalog knows about one model, keyed by its model
// name. Model names are assumed globally unique (OpenRouter namespaces its
// slugs, so the same weights on two routes are two distinct strings).
type Entry struct {
    Model    string            // the key: "claude-opus-4-8", "z-ai/glm-5.2", "text-embedding-3-small", …
    Provider string            // default route: "anthropic" | "google" | "openai" | "zai" | "openrouter"
    Routes   map[string]string // provider → wire id, for models reachable more than one way
                               // e.g. {"zai": "glm-5.2", "openrouter": "z-ai/glm-5.2"}
    Pricing   *agentkit.Pricing          // chat rates (nil for embedding entries) — for Conversation.Pricing
    Reasoning *ReasoningSpec             // chat reasoning vocabulary + default (nil where none/unknown)
    Context   int64                      // context-window tokens (advisory display/budgeting)
    Embedding *EmbeddingInfo             // embedding entries: rates + capabilities (nil for chat entries)
    Options   json.RawMessage            // default ProviderOptions fragment, when one is advisable (usually nil)
}

// ReasoningSpec describes a model's native reasoning vocabulary — the data
// that lets a consumer render, validate, and default reasoning up front
// (D6: validation is advisory, never in the request path). It answers three
// independent questions, and keeps them in three separate places: what values
// may be sent (Levels / Min,Max / Sentinels), which explicit switches the model
// accepts (CanEnable, CanDisable), and what the provider does when nothing is
// sent (Default).
type ReasoningSpec struct {
    Term       string           // "effort" | "thinking level" | "thinking budget" | "thinking"
    Kind       ReasoningKind    // Enum | Range | Toggle
    Levels     []string         // Kind==Enum
    Min, Max   int              // Kind==Range
    Sentinels  []Sentinel       // Range magic values (0=off, -1=dynamic)
    CanEnable  bool             // an explicit on-form exists and the model accepts it (Kind==Toggle only)
    CanDisable bool             // an explicit off-form exists and the model accepts it
    Default    ReasoningDefault // what the provider does on an unset value
}
type ReasoningKind int
const ( ReasoningEnum ReasoningKind = iota; ReasoningRange; ReasoningToggle )
type Sentinel struct{ Value int; Meaning string }

// ReasoningDefault answers "what happens if I send nothing?" — deliberately a
// different type from agentkit.ReasoningValue, which answers "what may I send?".
// Not every provider default is expressible as a value the caller could have
// sent, so typing the default as a ReasoningValue forces a false claim.
type ReasoningDefault struct {
    Mode  ReasoningDefaultMode
    Value agentkit.ReasoningValue // set only when Mode == DefaultFixed
}
type ReasoningDefaultMode int
const (
    DefaultUnaudited ReasoningDefaultMode = iota // zero value: neither measured nor sourced
    DefaultOff                                   // does not reason unless asked
    DefaultFixed                                 // equivalent to the caller sending Value
    DefaultDynamic                               // provider chooses per request; not caller-controllable
)

// EmbeddingInfo carries an embedding model's rates and capabilities.
type EmbeddingInfo struct {
    Pricing         agentkit.EmbeddingPricing
    NativeDimension int
    MinDimension    int // inclusive producible lower bound
    MaxDimension    int // == NativeDimension
    MaxInputTokens  int // advisory; the provider is the enforcer (D19)
}

// Lookup returns the entry for a model name; ok=false for an uncataloged name
// (which remains fully runnable — the caller just gets no conveniences).
func Lookup(model string) (Entry, bool)

// Resolve answers the two-axis query (a consumer's -provider/-model pair):
// provider=="" uses the entry's default route; a named provider uses the
// entry's route id for it. An uncataloged model, or a provider the entry has
// no route for, resolves to the name passed through verbatim — free-flow.
func Resolve(provider, model string) (routeProvider, wireModel string, entry Entry, ok bool)

// ListByProvider enumerates every entry reachable via a provider, as its
// default route or a listed route — catalog rendering for pickers/--help.
func ListByProvider(provider string) []Entry

// Check validates a ReasoningValue against a cataloged model's spec —
// advisory pre-flight for consumers that want errors before spending a round
// trip. Uncataloged model: ok=false, nothing to check against.
func Check(model string, v agentkit.ReasoningValue) (accepted bool, spec *ReasoningSpec, ok bool)
```

```go
// package catalog/openrouterx — typed builder over the ProviderOptions escape
// hatch (D9/D24): convenience, never a gate; unknown future knobs are written
// raw alongside it.

type Routing struct {
    Order          []string
    Only, Ignore   []string
    Sort           string   // "price" | "throughput" | "latency"
    MaxPrice       *MaxPrice
    Quantizations  []string
    ZDR            bool
    AllowFallbacks *bool
}
func (r Routing) ProviderOptions() json.RawMessage // emits {"provider":{...}}
```

**The data.** The catalog ships the maintained tables: chat rates (nano-USD `RateTier`s, including context-tiered models), reasoning specs, context sizes, routes, and embedding rates/capabilities, for the models we track. Rates and any estimated reasoning cells are a release-time re-verification item owned by the plan/release process. The authoritative values are pinned by **golden tests inside the package**: the shipped Go data and the recorded reference table cannot silently diverge (R-DQ16-AQWE). This decision deliberately does not restate the full tables; they are data, versioned with the package, edited in one place. The gathered source values live in research §6.5 (rates) and §7.1 (reasoning vocabularies).

**Two shapes of entry, distinguished by where the default route points.** Most entries default to a **native** provider — the vendor AgentKit has an adapter for — and may list additional routes (`glm-5.2` defaults to `zai` and also lists `openrouter`). A second shape defaults to the **aggregator**: vendors with no native adapter (xAI/Grok, DeepSeek, Moonshot/Kimi) are reachable only through OpenRouter, so their `Provider` **is** `"openrouter"` and their `Routes["openrouter"]` carries the vendor-namespaced slug (`x-ai/grok-4.5`, `deepseek/deepseek-v4-flash`, `moonshotai/kimi-k3`). The route entry is load-bearing, not decorative: `Resolve` falls back to `Entry.Model` when a provider has no route, so an aggregator-default entry that omitted its slug would resolve to a bare id OpenRouter does not serve, and the failure would surface only as a vendor 404 at call time (R-4MB8-ERDC).

**Slugs are a live-substrate claim.** That a slug is *well-formed* is checkable offline; that it is *real* is not — a golden test compares the table against itself and a mocked transport accepts whatever it is handed. Cataloging a mistyped or retired slug is therefore invisible to every hermetic test in the suite. Aggregator-routed entries consequently carry an integration-gated check that drives the real OpenRouter API and observes a completed round trip per slug (R-4NJ4-SJ41), which is the only test that can falsify the claim.

**The default is descriptive, never applied.** AgentKit sends no reasoning fields on an unset value (D6), so what a consumer gets by saying nothing is precisely what the vendor API would have given them. `Default` records that observed behavior so a consumer can *predict* the cost before sending; nothing reads it into a request, and no phase may make it do so. This is what keeps the recorded default true rather than aspirational: the catalog describes the provider, it does not configure it.

**Three shapes of default, because one of them is not a value.** A provider's behavior on silence is `DefaultOff`, `DefaultFixed` (equivalent to sending `Value`), or `DefaultDynamic` (the provider decides per request and the caller has no say). Only the middle one is expressible as a `ReasoningValue`, which is why `Default` is its own type. Two entries prove the split is real rather than pedantic: `deepseek-v4-flash` reasoned on 1 of 3 and then 2 of 3 identical requests, so no fixed value exists to record; and `gemini-2.5-pro`'s default is *also* exactly `Budget(-1)`, yet recording it that way would force a reader to decode a magic integer against `Sentinels` to learn who is in control. `Sentinels` says `-1` is *sendable*; `DefaultDynamic` says the provider *chooses*. Those are two facts and they live in two fields.

**`DefaultUnaudited` is the zero value on purpose.** Before this split, an entry that nobody had probed was indistinguishable from one measured as off, so unaudited data read as a positive claim. Making the zero value mean "unknown" turns that silent ambiguity into a mechanically detectable one (R-DMG6-B26E), consistent with failing loudly rather than defaulting quietly.

**Enable-ability and disable-ability are two permissions.** `CanEnable` and `CanDisable` are independent bools because the wire treats them independently: `grok-4.5`, `grok-4.20-multi-agent` and `kimi-k2.7-code` accept an explicit on and reject off with a 400, while `grok-4.20` accepts both and defaults to off. `CanEnable` is meaningful only for `Kind: Toggle` — on an enum or range you turn reasoning on by naming a level or a budget, so a separate bool would restate what `Levels`/`Min`/`Max` already say (R-DK0D-JIP0).

**Off-ness is stored, not derived, even where it is derivable.** For `Kind: Range` it *is* derivable — reasoning can be disabled exactly when zero is reachable, either through `Min == 0` or an off sentinel — and `gemini-2.5-flash` (`Min: 0`) versus `gemini-2.5-pro` (`Min: 128`, every legal request still thinks) is that derivation in action. It is not derivable for the other two shapes: a toggle's off-form may simply be rejected, and on an enum nothing but convention separates `gpt-5.4`'s `none` (genuinely off) from `gemini-3.5-flash`'s `minimal` (a floor, not off). A field that meant "measured" on two shapes and "inferred" on a third would be a trap, so `CanDisable` is measured everywhere and the range case is pinned by a consistency test (R-DL89-XAFP) that makes the redundancy impossible to get wrong.

Settled choices:
- **Keyed by model name; names assumed unique.** The primary consumer query is "user typed one string" — a compound key would demand the provider *before* the lookup, defeating resolution. OpenRouter's vendor-namespaced slugs make cross-route collisions distinct strings in practice; uniqueness is assumed, not policed (operator decision — no duplicate-detection machinery).
- **Provider in the value; `Routes` for multi-route models; overridable.** `Resolve(provider, model)` honors a consumer's explicit provider choice (`-provider=openrouter -model=glm-5.2` → route id `z-ai/glm-5.2`); the routed-to-OpenRouter case is then costed by OpenRouter's reported figure (D16 precedence), so the entry's direct-route rates are never misapplied to the aggregator route.
- **Advisory, structurally enforced.** Root and provider packages never import `catalog` (R-DR92-OIN3); the request path cannot consult it even by accident. Consumers alone wire its data into `Conversation.Pricing`, `Embedder.Pricing`, `Gen.Reasoning` defaults, and `ProviderOptions`.
- **Typed builders live here, not in core.** Vendor-shaped conveniences (`openrouterx.Routing`) emit the same opaque fragments a consumer could write by hand — comfort without closing the escape hatch.
- **Uncataloged ⇒ pass-through, everywhere.** Every helper degrades to "here's your string back, no metadata" — the catalog can never become a gate.

**Rejected.**
- *`Default` typed as `agentkit.ReasoningValue`* — the previous shape. It can only say "the default equals what you would have got by sending X", which is false for every provider whose default is an opaque or per-request policy, and its zero value conflated "dynamic", "off", and "nobody looked". `ReasoningDefault` states the mode first and the value only where a value honestly exists.
- *A portable `Dynamic()` constructor on `ReasoningValue`* — dynamic is natively sendable on exactly two Gemini models (`Budget(-1)`); exposing it portably would make AgentKit synthesize a concept for providers that lack one, the same substitution native-first forbids (D6).
- *One fixed default applied everywhere (e.g. `medium`)* — conceptually simple, unworkable in fact: nine tracked models have no levels to receive it, six default to off so injecting a level silently turns reasoning on and bills for it, `gemini-2.5-pro` has no off at all, and genuinely dynamic models have no level to match. It also makes the library substitute a value the consumer did not choose. Pass-through matches the vendor by construction and needs no code, since an unset value already sends nothing.
- *Deriving `CanDisable` from `Min`/`Sentinels` for ranges instead of storing it* — makes one field mean "measured" on toggles and enums but "inferred" on ranges; stored-plus-consistency-test keeps the meaning uniform.
- *Folding `CanEnable` into `CanDisable` as a single tri-state* — they are independent permissions the wire grants separately; a single field cannot express "on accepted, off rejected", which is the state three tracked models are in.
- *Compound (provider, model) keys* — demands the provider before the primary lookup; operator-rejected in favor of unique names + provider-in-value.
- *Duplicate-key golden policing* — machinery for a collision the slug conventions make hypothetical; assume uniqueness until reality objects (operator decision).
- *Exported per-provider model constants* — a second driftable model list; discoverability is catalog data rendered by consumers.
- *Catalog consulted by the orchestrator (auto-pricing on Send)* — re-couples running to catalog coverage through the back door; the consumer's explicit wiring is the design.
- *Per-provider inspector interfaces (`ReasoningInspector`/`EmbeddingInspector`)* — the former credential-blind introspection surface; one data package with plain lookups replaces N interface implementations and the consumer's provider-keyed map of them.

**Verification.**
- R-DMDH-5FOB — `Lookup` on a cataloged chat model returns its provider, rates, reasoning spec, and context size; on a cataloged embedding model returns its `EmbeddingInfo`; on an unknown name returns `ok=false` — all with no network, no credentials, and no client construction.
- R-DNLD-J7F0 — `Resolve("", m)` uses the entry's default provider and its wire id; `Resolve(p, m)` with a listed route returns that route's wire id (the glm-5.2 → `z-ai/glm-5.2` case); an uncataloged model or unrouted provider returns the input name verbatim with `ok=false` — never an error, never a block.
- R-DOT9-WZ5P — `ListByProvider` returns every entry whose default or routed provider matches, and nothing else; a provider with no entries returns an empty list.
- R-DQ16-AQWE — golden: the shipped catalog data (chat `RateTier` values, reasoning specs including every `Kind`, `Levels`, `Min`/`Max`, `Sentinels`, `CanEnable`, `CanDisable` and `Default` cell, embedding rates and capability rows, routes) equals the package's recorded reference table, so a transcription slip cannot ship silently.
- R-DHKK-RZ7M — across every shipped entry carrying a `ReasoningSpec`, `Default.Value` is non-zero **exactly when** `Default.Mode == DefaultFixed`: a `DefaultOff`, `DefaultDynamic`, or `DefaultUnaudited` entry carries the zero `ReasoningValue`, and a `DefaultFixed` entry never does. A `DefaultDynamic` entry that smuggled in a value (the `gemini-2.5-pro` `Budget(-1)` temptation) fails this.
- R-DISH-5QYB — for every shipped entry whose `Default.Mode == DefaultFixed`, its own spec accepts its default: `spec.Accepts(spec.Default.Value)` is true. A default the model could not have been sent is a contradiction in the data.
- R-DK0D-JIP0 — across every shipped entry, `CanEnable == true` implies `Kind == ReasoningToggle`; no `ReasoningEnum` or `ReasoningRange` entry sets it, since on those shapes on-ness is expressed by naming a level or budget.
- R-DL89-XAFP — across every shipped entry with `Kind == ReasoningRange`, `CanDisable` equals `Min == 0 || <a Sentinel whose Meaning is "off" exists>`. `gemini-2.5-flash` (`Min: 0`, off sentinel) is true and `gemini-2.5-pro` (`Min: 128`, no off sentinel) is false; flipping either cell fails, which is the drift this stored-plus-derived redundancy exists to catch.
- R-DMG6-B26E — no shipped chat entry carrying a `ReasoningSpec` has `Default.Mode == DefaultUnaudited`; adding a model without establishing its default fails the suite rather than shipping an unrecorded default that reads as "off".
- R-DNO2-OTX3 — `spec.Accepts(agentkit.EnableReasoning())` is true exactly when `CanEnable` is set, and `catalog.Check(model, agentkit.EnableReasoning())` reports the same for a cataloged model; on a `Kind == ReasoningEnum` or `ReasoningRange` entry it is false regardless of `CanDisable`.
- R-DOVZ-2LNS — live (integration-gated, real OpenRouter credentials): for each aggregator-routed entry, the catalog's `CanDisable` claim matches the real API — sending the wire's off-form returns a completed response for every `CanDisable: true` entry, and is rejected with a provider error for every `CanDisable: false` entry (`grok-4.5`, `grok-4.20-multi-agent`, `kimi-k2.7-code` currently). No hermetic test can falsify this: a mock accepts whichever fragment it is handed, so only the vendor can say whether a model may be switched off.
- R-DR92-OIN3 — structural: neither root `agentkit` nor any provider sub-package imports `agentkit/catalog` (asserted mechanically over the module's import graph), so the request path provably cannot consult it.
- R-4MB8-ERDC — every catalog entry whose default `Provider` is `"openrouter"` carries a non-empty `Routes["openrouter"]` vendor-namespaced slug (one containing `/`), and `Resolve("", model)` on each returns provider `"openrouter"` with that slug rather than the bare entry name; each also appears in `ListByProvider("openrouter")`. A bare-id entry (no route) fails this, which is the transcription slip it exists to catch.
- R-4NJ4-SJ41 — live (integration-gated, real OpenRouter credentials): each aggregator-routed slug the catalog ships is accepted by the real OpenRouter API — a minimal round trip per slug returns a completed response, not a model-not-found error — proving the slugs name models that actually exist rather than plausible strings a mock would accept.
- R-DSGZ-2ADS — `openrouterx.Routing.ProviderOptions()` emits exactly the `{"provider":{...}}` fragment its fields describe (order/only/sort/max_price/zdr, omitting unset fields), byte-comparable against hand-written JSON, and the emitted fragment round-trips through `Request.ProviderOptions` merging (R-CXZH-I0UF) unchanged.
