# Decision 37 — `toolkit`: `WebFetch` — page fetch to markdown

**Decision.** The `toolkit` package gains a `WebFetch` tool: AgentKit's own HTTP fetch of a
URL whose HTML comes back converted to markdown, so an agent can read the pages a search
turned up. It is deliberately **not** built on any external service (the Brave API has no
fetch endpoint — research §19.1): a plain GET, a conversion, a cap. No credential, no LLM
pass — the fetched content goes back to the calling model, which does its own extraction.

```go
// package toolkit

// WebFetch returns a tool that fetches a URL and returns its content,
// converting HTML to markdown.
func WebFetch() agentkit.Tool
```

Settled choices:

- **Input surface.** Two parameters, snake_case per the toolkit convention:

```go
type webFetchInput struct {
	URL            string `json:"url"`                       // required; http or https
	TimeoutSeconds int    `json:"timeout_seconds,omitempty"` // default 10; 1–120
}
```

  `url` must be absolute with scheme `http` or `https`; anything else (ftp, file, a
  relative path) is an input error and no request is made. `timeout_seconds` bounds the
  whole request (on top of the caller's context), defaulting to **10**; values outside
  1–120 are rejected so a confused agent cannot wedge a turn. The agent raises it
  deliberately for slow origins.
- **The fetch.** Raw `net/http` (D12), redirects followed per Go's default (10 hops), no
  retry — a failed fetch is signal the agent should see and route around. The body read is
  capped at **5 MB**: a larger body is an error, not a silent truncation, bounding memory
  before the 30k `capOutput` (D27) ever sees the result.
- **By content type.** The response's `Content-Type` decides (sniffed with
  `http.DetectContentType` when the header is absent), mirroring `Read`'s refusal
  posture (D28):
  - `text/html` → converted to markdown (below);
  - any other `text/*` (plain, markdown, CSV, JSON served as text, …) → returned verbatim;
  - non-text (images, PDFs, binaries) → a tool error naming the detected type, no content.
  Bytes are treated as UTF-8.
- **The markdown renderer, in-house on `golang.org/x/net/html`.** The stdlib has no HTML
  parser, so the module takes `x/net/html` — the Go team's own HTML5 tokenizer/parser and
  the module's first external dependency (operator-approved; recorded in Conventions) —
  and hand-rolls a small renderer on top. No third-party converter library. The renderer
  keeps what an agent reads and drops what it doesn't:
  - dropped entirely: `script`, `style`, `head`, `template`, comments;
  - structure: `h1`–`h6` → `#`-prefixed headings; `p`/`div`/`br` → paragraph and line
    breaks; `ul`/`ol`/`li` → `-` / `1.` items; `pre`/`code` → fenced/backticked code;
    `blockquote` → `>` lines; table rows → cells joined with ` | `;
  - inline: `a` → `[text](href)`; other inline markup flattens to its text;
  - entities decoded (`x/net/html` does this in tokenization); whitespace collapsed the
    way HTML rendering collapses it.
  The goal is faithful, readable text — not a spec-complete HTML-to-markdown engine.
- **Composed alongside, never inside, `All`.** Like `WebSearch` (D36), the tool is not in
  `All(root)`: it is keyless but reaches the network, and `All`'s contract stays the local
  root-confined set (D27).
- **Test seam.** Unit tests drive the tool against in-package `httptest` servers (crafted
  HTML, content types, redirects, oversized and hanging responses) plus direct renderer
  tests over crafted fragments. No integration-tagged tests; nothing external is
  contractual here beyond HTTP itself.

**Rejected.**
- *An LLM summarization pass inside the tool (the Claude Code `WebFetch` shape, with a
  `prompt` parameter)* — drags a provider client, model choice, and spend into a toolkit
  tool and inverts the library's layering; the calling model is already an LLM.
- *Backing fetch on a third-party reader/extraction service* — the point of the pair is no
  external dependencies beyond the one search API; and Brave itself offers no fetch.
- *A hand-rolled regex tag-stripper (keeping the module zero-dep)* — worse text and an
  edge-case tarpit; `x/net/html` is the de-facto standard parser, maintained by the Go
  team, and the approved exception.
- *Returning raw HTML* — markup routinely multiplies token count several-fold over the
  visible text; the conversion is the tool's value.
- *Silently truncating an over-5 MB body* — a half-read page presented as the page is
  corruption; the error names the cap and the agent moves on.

**Verification.**
- R-1LWA-VRRX — the tool's declared name is `WebFetch`; its schema's `required` set is exactly `["url"]`; its properties are exactly `url` and `timeout_seconds`, each carrying a non-empty `description`.
- R-1N47-9JIM — a non-http(s) URL (`ftp://…`, `file://…`, a scheme-less path) returns an input error and no HTTP request is made.
- R-1OC3-NB9B — a `text/html` response converts to markdown preserving block structure — `h1`–`h6` as `#`-headings, list items as `-`/`1.` lines, `pre` content fenced — while `script`, `style`, and `head` content is absent from the output.
- R-1QRW-EUQP — inline conversion: `<a href>` becomes `[text](href)` and HTML entities (e.g. `&amp;`, `&#39;`) arrive decoded in the output.
- R-1RZS-SMHE — a non-HTML `text/*` response (e.g. `text/plain`) is returned verbatim, unconverted.
- R-1T7P-6E83 — a non-text response (e.g. `image/png`, `application/pdf`) returns a tool error naming the detected content type, with no body content in the result.
- R-1UFL-K5YS — a body exceeding 5 MB returns an error naming the cap rather than truncated content; redirects are followed en route (a fetch through a redirect returns the final page's content).
- R-1VNH-XXPH — `timeout_seconds` defaults to 10 when omitted and rejects values outside 1–120 with an input error; against a server that never responds, a call with a small `timeout_seconds` fails with a timeout error in that order of time instead of hanging.
