# Decision 25 — OpenAI credentials: API key and ChatGPT subscription

**Decision.** The `openai` package's closed credential set (D5) has two members — the only package with more than one. The credential type selects the auth mechanism **and the transport it drags along** (endpoint, headers, body constraints): mechanism is hidden inside the provider; the pick is explicit, structural, and compile-time. The refresh/login machinery lives in an **opt-in subpackage `openai/subscription`** so consumers that never use it never import disk or OAuth code; the `TokenSource` seam it feeds is declared in `openai` proper (the credential cannot depend on the opt-in package — dependency points inward).

```go
// package openai

type Credential interface{ isCredential() } // closed: exactly two members
type APIKey string                          // platform API, metered
func Subscription(ts TokenSource) Credential // ChatGPT subscription, flat-rate

// TokenSource supplies the living bearer for subscription auth. Implemented by
// subscription.Store; any implementation works (the seam is what's contractual).
type TokenSource interface {
    Token(ctx context.Context) (bearer, accountID string, err error)
}

func New(cred Credential, opts ...Option) *Provider // one wire: Responses (D5)
```

| baked into the handle | `APIKey` | `Subscription` |
|---|---|---|
| endpoint | `api.openai.com/v1/responses` | `chatgpt.com/backend-api/codex/responses` |
| auth | static `Authorization: Bearer` | per-request bearer from `TokenSource` + `chatgpt-account-id` + `originator: codex_cli_rs` + `OpenAI-Beta: responses=experimental` |
| body constraints | `store:false`, `instructions`, encrypted-reasoning include (already fixed adapter behavior, D9) | identical — the existing adapter already satisfies the backend's requirements |
| model set | vendor judges (free-flow, D5) | backend gates to the subscription's models; rejection is the vendor's loud error |
| cost basis | actual API rates | **notional API-rate-equivalent** (research §15.4) — same D16 resolution over the same supplied rates, no flag, documented here |
| `Name()` / `Error.Provider` / log label | `openai.apikey` | `openai.subscription` |

```go
// package openai/subscription — opt-in: disk + OAuth machinery, never imported
// by the core provider path.

// Load opens an existing auth file (the codex-CLI-compatible JSON shape,
// research §15.1) at exactly the path the consumer names — no path discovery,
// no env reading (product: no ambient credential sourcing).
func Load(path string) (*Store, error)

// Store implements openai.TokenSource over the auth file: it returns the
// current access token, refreshing proactively when the JWT exp is near (and
// reactively on 401 via the provider's retry of an auth-expired category),
// writing rotated tokens back atomically at mode 0600, single-flight so
// concurrent requests do not race the file. account_id is read from the file's
// plain tokens.account_id field (no JWT decoding). Token values are never logged.
func (s *Store) Token(ctx context.Context) (bearer, accountID string, err error)

// BeginLogin starts the headless manual-paste PKCE flow (research §15.3):
// generate the PKCE verifier/challenge and state, build the authorize URL,
// return a Flow holding them. Pure computation — no network, no terminal IO.
func BeginLogin() (*Flow, error)

// AuthorizeURL returns the auth.openai.com authorize URL the consumer
// presents to the user however it likes (print, TUI, browser open).
func (f *Flow) AuthorizeURL() string

// Complete finishes the flow with the redirect URL the user pasted back:
// parse it, verify state against the Flow, exchange the code (with the
// verifier) at auth.openai.com, and write a fresh auth file at path (0600).
// Empty or unparsable input fails with an explicit error naming that the
// full redirect URL was expected — distinct from a state mismatch — and
// neither failure reaches the token endpoint. Plain functions a consumer
// CLI wraps; AgentKit ships no binary and touches no terminal.
func (f *Flow) Complete(ctx context.Context, path, pastedRedirectURL string) error
```

Settled choices:
- **One provider, one wire, two credentials.** The subscription path speaks the same Responses shape the adapter already implements — `store:false`, mandatory `instructions` (System→instructions), `include:["reasoning.encrypted_content"]` are the D9 fixed behaviors, which is precisely why this is an auth+transport variant, not a second adapter. The transport differences (host/path, extra headers, bearer source) key off the credential type internally.
- **The forced pick is structural.** `APIKey` and `Subscription` take different Go types; there is no mode string, no auto-detect, no fallback (openai-auth.md's settled rule, hardened from env-var vocabulary into the type system by D5).
- **Mechanism in agentkit, policy in the consumer.** `subscription.Load(path)` takes an explicit path — resolving *which* path (an env var, `$CODEX_HOME`, `~/.codex/auth.json`) is consumer policy, as is wiring the login flow into a CLI. The helper reads and maintains exactly the file it is handed: the product's no-ambient-credentials rule holds with the one documented, opt-in exception.
- **No terminal IO in the library.** The login flow is value-in/value-out: `BeginLogin` hands the consumer the authorize URL as a value; the consumer does all prompting, printing, and reading, and hands the pasted redirect URL back as a value to `Complete`. No `io.Reader`/`io.Writer` appears anywhere in the package's surface.
- **Independent lineages; respect the codex CLI's file.** Refresh rotates a shared refresh-token lineage (research §15.3), so a file created by AgentKit's login flow is the one AgentKit refreshes; pointing `Load` at the official codex CLI's own file works for read/use but invites rotation contention — documented, and the live test discipline below observes it.
- **Cost: notional, undistinguished, documented.** Subscription turns resolve cost exactly like API-key turns (D16); the figure is API-rate-equivalent, not spend. No basis flag (operator decision); this table and the package docs are the statement.
- **Labels carry the mode.** `Name()` returns `openai.apikey` / `openai.subscription` — errors, D15 log records, and consumer displays distinguish the modes, since their cost semantics differ.
- **Build-time pin-downs, not spec unknowns.** The exact OAuth `scope` string and the existence of a device-code flow for the public client id are captured during implementation by observing one real login (research §15.3); neither changes this seam's shape.

**Rejected.**
- *`NewCodex` / vendor-codename constructors* — names the vendor's tool, not the thing; operator-rejected.
- *Auth-qualified constructor names (`NewAPIKeyProvider`/`NewSubscriptionProvider`)* — rejected in D5: name = wire × auth explodes; the credential is a typed parameter.
- *A separate `codex`/second provider package* — same models, same wire shape, same vendor; two packages would fork the adapter to vary auth.
- *Auto-detect (key present ? env ? file exists ?)* — silent fallback between billing modes is exactly the surprise the explicit pick exists to prevent.
- *`OPENAI_AUTH_MODE` env resolution inside agentkit* — agentkit never reads env; that resolution is consumer policy (openai-auth.md's catalog `Resolve` sketch lives in the consumer).
- *Storing `account_id` by decoding the id-token JWT* — the file already carries it as a plain field (verified locally, research §15.1); decoding adds fragility for nothing.
- *Interactive `Login(ctx, path, LoginIO)` doing its own printing and stdin read* — the original shape, removed: a library owning terminal IO blocks silently with no prompt of its own and hijacks the consumer's input loop (a REPL consumer loses its dispatcher for the duration, proven in practice by agentrepl). Presentation is consumer policy; the library exposes only values.

**Verification.**
- R-DG9Z-8KYU — a `Send` through `openai.New(openai.Subscription(ts))` (fake `TokenSource`, `httptest` backend) posts to the codex backend path with `Authorization: Bearer <ts-bearer>`, `chatgpt-account-id: <ts-account>`, `originator: codex_cli_rs`, and `OpenAI-Beta: responses=experimental` headers, body carrying `store:false`, non-empty `instructions`, and the encrypted-reasoning include — while `openai.New(openai.APIKey(k))` continues to post to the platform path with none of the subscription headers.
- R-DHHV-MCPJ — a `Store` whose access token is expired refreshes at the token endpoint (fake OAuth server), retries carry the new bearer, the rotated tokens are written back atomically with mode `0600`, and N concurrent `Token` calls produce exactly one refresh request (single-flight, asserted on the fake server's request count).
- R-I8OP-9XZ7 — `BeginLogin` + `Complete` against a fake authorize/token server drive the manual-paste PKCE flow — `AuthorizeURL()` carries the S256 challenge and state; `Complete` verifies state and exchanges the code with the verifier — and write an auth file whose JSON shape matches research §15.1, mode `0600`; a pasted callback with a wrong `state` is rejected without a token exchange.
- R-I9WL-NPPW — `Complete` with an empty or unparsable pasted line fails with an error naming that the full redirect URL was expected — a distinct message from the wrong-`state` rejection — and no request reaches the fake token endpoint (asserted on its request count).
- R-DL5K-RNXM — `Name()` returns `openai.apikey` for an `APIKey`-built handle and `openai.subscription` for a `Subscription`-built one, and a provider error from each carries that label in `Error.Provider`.
- R-DJXO-DW6X — **live** (gated on the presence of a local codex-compatible auth file; skips cleanly otherwise): `subscription.Load` + `Token` yields a bearer the real ChatGPT backend accepts on one completed round trip (a short real `Send` returning an assembled non-error message) — read/use only, no refresh forced against the shared-lineage file — proving the endpoint/header/body contract against the real service.
