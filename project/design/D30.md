# Decision 30 — `toolkit`: `Glob` and `Grep` semantics

**Decision.** The two search tools follow the prompts-service result shape — sorted JSON arrays of base-relative, slash-separated paths (research §16.1) — with three hardenings: recursive `**` globbing, `.git` exclusion, and binary skipping.

```go
// package toolkit

type globInput struct {
	Pattern string `json:"pattern"`        // required; glob, ** = any depth
	Path    string `json:"path,omitempty"` // dir to search; default = root
}

type grepInput struct {
	Pattern string `json:"pattern"`        // required; Go regexp, matched per line
	Path    string `json:"path,omitempty"` // file or dir; default = root
	Glob    string `json:"glob,omitempty"` // optional base-name filter (path.Match)
}
```

Settled choices:

- **`Glob`** returns a JSON array of matching file paths, sorted, relative to the search base, slash-separated. A pattern without `**` keeps `filepath.Glob` semantics. A pattern containing `**` matches recursively at any depth via a hand-rolled `WalkDir` + per-segment matcher — `filepath.Glob` has no `**` (research §16.3), and models trained on Claude Code's Glob reach for `**/*.go` reflexively, so a silently single-level Glob feeds an unattended agent incomplete file lists. No new dependency (`doublestar` rejected in D27).
- **`Grep`** compiles the pattern as a Go regexp, searches the given file — or walks the given directory (default: root) — and returns a sorted JSON array of `file:line:text` matches; the optional `glob` input filters candidate files by base name. An invalid regexp is an error.
- **`.git` exclusion.** Both `Glob`'s `**` walk and `Grep`'s directory walk skip directories named `.git` — and only `.git`: agents legitimately search `.github`, `.claude`, and other dotdirs, but `.git` object stores dominate results with garbage.
- **Binary skipping (`Grep` only).** A file whose first 8 KB contains a NUL byte is skipped (the git heuristic, research §16.3), so vendored blobs and build artifacts stop drowning matches.
- No gitignore parsing: real complexity for marginal gain; `Bash` with `grep`/`find`/`rg` remains the escape hatch.
- Empty result sets are the JSON `[]`, never an error — "nothing matched" is information.

**Rejected.**
- *`filepath.Glob` alone (prompts service)* — `**` silently degrades to one `*` segment; the worst failure mode is the one the model can't see.
- *Skipping all dot-directories* — over-broad; `.github/workflows` and `.claude/` are legitimate search targets.
- *gitignore awareness* — a parser plus per-directory stacking semantics to save the model an occasional narrowed search.
- *Streaming/paginated results* — D27's 30,000-character cap plus narrower patterns cover the oversized-result case without a cursor protocol.

**Verification.**
- R-MEFY-KPMC — `Glob` with a plain (no-`**`) pattern returns exactly the `filepath.Glob` matches as a sorted JSON array of base-relative slash paths.
- R-MFNU-YHD1 — `Glob` with a `**` pattern (e.g. `**/*.go`) matches files at every depth, including the base itself and nested subdirectories.
- R-MGVR-C93Q — `Glob`'s recursive walk returns no paths under any `.git` directory, while a sibling `.github` directory's files still match.
- R-MJBK-3SL4 — `Glob` with a pattern matching nothing returns the JSON array `[]`, not an error.
- R-MKJG-HKBT — `Grep` over a directory returns each regexp-matching line as `file:line:text` (base-relative slash path, 1-based line), sorted, as a JSON array.
- R-MLRC-VC2I — `Grep` with `path` naming a single file searches only that file, and `glob` restricts a directory search to files whose base name matches (a match in an excluded file does not appear).
- R-MMZ9-93T7 — `Grep`'s directory walk skips `.git` directories: a matching line inside `.git/` is not reported.
- R-MO75-MVJW — `Grep` skips binary files: a file containing the pattern but with a NUL byte in its first 8 KB yields no match entry.
- R-MPF2-0NAL — `Grep` with an invalid regular expression returns an error naming the pattern problem.
