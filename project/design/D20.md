# Decision 20 — Embedding usage & pricing: the data shapes

**Decision.** Embeddings keep their **own** small usage and pricing types — `EmbeddingUsage` and a flat single-rate `EmbeddingPricing` — because the chat `Usage`/`Pricing` (D8/D16) carry output, reasoning, cache tiers, and context-length tiers that do not exist for embeddings (research §12.4). They reuse the root `Cost` type (D16) so dollar accounting is one shared currency. Like chat's `Pricing`, `EmbeddingPricing` is a **pure data shape**: providers hold no rate data and no model registry (D5/D19); the consumer supplies the row on `Embedder.Pricing` (D18), typically from the advisory catalog (D26), which also carries each cataloged embedding model's capability metadata (native/producible dimensions, max input tokens) for up-front display and validation — advisory only, never consulted in the request path.

```go
package agentkit

// EmbeddingUsage reports an embed call's token consumption. Embeddings bill
// input tokens only — no output, no reasoning, no cache tiers — so this is a
// deliberately smaller type than the chat Usage (D8). Total == InputTokens for
// every supported provider; it is kept as its own field for symmetry with chat
// and forward room. Summed across a batch's internal chunks (D19).
type EmbeddingUsage struct {
    InputTokens int64
    Total       int64 // == InputTokens
}

// EmbeddingPricing is one model's flat per-input-token rate in nano-USD (1e-9
// USD) — integer, so cost is exact with no float drift, exactly like chat
// Pricing (D16). No tiers and no output term: embedding models do not tier by
// context length, so a single rate is both sufficient and exact.
type EmbeddingPricing struct {
    InputToken int64 // nano-USD per input token
}

// Cost computes an embed call's nano-USD cost: InputTokens · InputToken.
// Returns the shared root Cost type (D16), so Cost.USD() and the Embedder's
// cumulative TotalCost() (D18) work identically to chat.
func (p EmbeddingPricing) Cost(u EmbeddingUsage) Cost
```

Settled choices:
- **A separate `EmbeddingUsage`/`EmbeddingPricing` pair, not the chat types.** Reusing `Usage`/`Pricing` would carry ~six always-zero fields and a `(Output+ReasoningOutput)·rate` term that is structurally wrong for input-only billing (research §12.4). The small pair states exactly what embeddings bill.
- **Flat single-rate pricing, no `RateTier`.** No embedding model tiers by context length; the tiered machinery earns its surface only on chat models.
- **The root `Cost` type is shared.** One currency across both capabilities; `Cost.USD()`, `EmbedResult.Cost()`, and `Embedder.TotalCost()` behave identically to chat.
- **Cost resolution is D18's (per D16's philosophy): supplied row → computed; nil → zero + `WarnCostUnknown`.** There is no unpriced *error* state and no gate; the warning keeps the zero honest. This decision owns only the data shapes and the math.
- **Rates and capability metadata live in the catalog (D26), keyed by model name with everything else.** The former per-provider embedding registries, the credential-blind `EmbeddingInspector`, and the exported embed-model constants are deleted with the model-knowledge eviction (D5); the catalog's embedding entries carry `EmbeddingPricing` plus native dimension, producible-dimension range, and max input tokens, with the catalog's own golden tests (D26) holding the data to the values recorded there.

**Rejected.**
- *Per-provider embedding registries + `Pricing(model)` SPI + `EmbeddingInspector`* — the previous design; provider-held model knowledge, evicted per D5. Capability introspection survives as catalog data (D26); the "supported ⇒ priced ⇒ describable" structural guarantee is deliberately traded for day-one model freedom, with the D16 warning covering the honesty gap.
- *Reusing chat `Usage`/`Pricing` for embeddings* — unchanged rejection.
- *`float64` USD* — unchanged rejection; nano-USD integers are exact.
- *Tiered embedding pricing* — unchanged rejection; dead structure.

**Verification.**
- R-YPAA-0MYX — for each provider, a recorded embeddings response maps to `EmbeddingUsage` (OpenAI `usage.prompt_tokens`; Google `usageMetadata.promptTokenCount`) with `Total == InputTokens`, and a multi-chunk batch's usage is the sum across its chunks.
- R-D8YK-XYIO — `EmbeddingPricing.Cost(u)` equals `u.InputTokens × InputToken` in exact integer nano-USD, returning the shared root `Cost` type.
